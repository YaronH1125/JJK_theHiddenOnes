## 1. 现状与本次要解决的问题

工程里已经有两个 UI 层：

| 现有内容 | 位置 | 本次处理 |
| --- | --- | --- |
| 开发用 HUD（双方四资源数值 + 状态文本 + 模式与训练开关） | `UCombatHudWidget` | 保留为调试层，正式层另建；两者可同时可见（见 §7 调试分层） |
| 准星（远程形态显示、蓄力向心收拢、领域变色） | `AArenaCrosshairHud::DrawCrosshair` | 规格沿用，只补外圈蓄力进度与炮口受阻提示 |
| 训练设置面板 | `UTrainingPanelWidget` | 功能不动，本轮只统一视觉令牌 |

需要解决的问题有三个：

1. **可读性**：开发 HUD 用卡片堆叠，双方八条数值条平铺，正式玩法需要的"我刚能不能开炮""领域几秒后结束"读不出来。
2. **缺少状态量**：蓄力强度、已支付咒力上限、超级炮冷却、领域剩余时间与下次发炮、双领域压制，目前在 HUD 上完全没有表达。
3. **缺取舍**：现在双方信息等权，但玩家在战斗中只需要自己的资源 + 对手的生命，对手资源属于调试信息。

## 2. 版式决策：分区式

- **上左（玩家）/ 上右（对手）**：头像 + 名字行 + 生命条 + 咒力条（+ 玩家侧行动资源条）
- **顶部中央**：模式徽标；领域相关的状态文字（结印 / 结界名 / 倒计时 / 压制横幅）
- **下中**：形态圆盘 + 蓄力环 + 蓄力读数
- **右下**：技能区（单行三圆钮：Q / E / R，R 带领域充能环）
- **屏幕中央**：只有准星与命中飘字

**领域能量集中在右下大招按钮上**（v5.0 改定），不再占用顶部中央。

**玩家一侧有完整资源条；对手一侧为生命 + 咒力。** 理由是第三人称对战里玩家的注意力集中在擂台中央，对手的咒力/行动资源无法转化为即时决策（看不到对手的按键意图，只能看到可见动作），却会持续占用上方视野。行动资源是玩家自己的资源（闪避/取消），因此只在玩家侧出现。

首版已经确认"提前提供开发用常驻双方生命及资源 UI"（见 [01](01_需求说明.md) §5），因此对手完整数值不删除，而是移到调试层（§7），默认关闭。

## 3. 组件与状态映射

### 3.1 生命（上左/上右）

| 元素 | 数据来源 | 规则 |
| --- | --- | --- |
| 名条 | 角色名 + `EFighterRole` | `P1 石流龙`（青）/ `P2 石流龙`（橙红），身份色只用于名条与描边 |
| 主填充 | `Health / MaxHealth` | 斜切平行四边形，冷白到浅青渐变，两侧读数节奏一致 |
| 虚血残影 | `Health` 下降事件 | 受伤后 0.6 秒延迟、0.35 秒回落；低于 30% 时条体呼吸脉冲 |
| 数值 | `Health` | 常驻低对比；受伤瞬间放大高亮 240ms |

数值取整方式与 [08](08_石流龙战斗系统设计.md) §7.2 的"统一定义小数属性和最终显示取整方式"一致，HUD 不自行四舍五入出第二套口径。

### 3.2 领域状态（v5.0：改由大招按钮承载）

领域是本项目最有辨识度的机制，且与形态是**两条独立状态轴**（见 [08](08_石流龙战斗系统设计.md) §8.1），不能用形态圆盘兼职显示。

**v5.0 的主要改动**：按用户要求（"参考鸣潮的大招充能直接在领域展开图标这显示"），**领域能量改为集中在右下大招（R）按钮的充能环上**，**顶部中央原有的双方弧槽已移除**。

| 阶段 | 表现 | 数据 |
| --- | --- | --- |
| 待机 | **大招按钮的同心充能环**（浅青蓝，见 §4 令牌）填至当前能量 | `Energy / MaxEnergy`（0/100） |
| 满能量 | 环转亮 + **向外扩散的柔光晕 + 环外粒子外溢**（照用户提供的参考）；`R 可展开 · 极宴流光` 提示 | `Energy >= DomainConfig.EnergyCost` |
| 结印中 | 1 秒径向进度环，刻度依次点亮，细线警示可被打断 | `CastTime`（1.0s） |
| 展开中 | 大字 `领域展开 · 极宴流光` + 倒计时 + **三个发炮刻度**（0.3/2.3/4.3）+ 在途球数 | `Duration`（6s）、`FirstOrbDelay`、`OrbInterval` |
| 自动炮跳过 | 该刻度变灰并标注原因（咒力不足 / 受击 / 目标受保护） | `OrbCost` 65 与当前咒力比较 |
| 双领域压制 | 顶部中央 `领域受压制 · 自动炮暂停` 横幅 + 双方之间的水平链锁横杠 + **受压制方头像外圈转紫呼吸** | 双方 `bSuppressed` |
| 结束 | 环回落到当前能量，环境色相回到基础层 | 会话失效 |

"下一发还有多久"必须显示，因为领域期间玩家不再手动蓄力（[08](08_石流龙战斗系统设计.md) §8.2 建议期间禁用远程手动炮），此时段内玩家唯一的输出节奏就是这三次自动炮。

**代价（需知晓）**：移除顶部弧槽后，**对手的领域能量连续进度（0–100%）不再可见**。原设计里双领域压制需要同时看两边，现在改为由压制横幅 + 链锁横杠 + 头像外圈变色表达"压制已发生"，但无法预判对手还差多少能展开。设计板 03·e 记了这条取舍，并给了一个不新增条的补救建议（在 P2 头像框加一圈同语言的充能环）——**尚未实现，需用户确认**。

领域名在实现中建议仍以 `DomainExpansion` 标识，不把工作名写死到公共系统（[08](08_石流龙战斗系统设计.md) §2 同口径）。

| 蓄力组件 | 下中 | 围绕形态圆盘的同心外环 | 见 §3.5 |
| 形态圆盘 | 下中（蓄力环圆心） | 近战/远程图标 + 文字 + 再切间隔弧 | `EFighterStance`，只读 |

**行动资源为什么改为长条**（v4.0）：它原本是 5 格离散方块，理由见 §3.3.1 的"整数决策"。但用户要求"条状化"后，改用**连续长条 + 上缘 4 道 2px 短刻度**：刻度只挂上缘、不贯穿条高——贯穿会立刻被读成 5 个格子；实测 1px 刻度在缩放后被抗锯齿摊薄到几乎不可见，故取 2px。

**行动资源为什么在玩家侧**：按 [01](01_需求说明.md) §5 与 [08](08_石流龙战斗系统设计.md) §7.1，它是**玩家自己**的资源（闪避 1、取消闪避合计 2、停用 1s 后每秒 +1），早期版本误置到对手侧，v4.0 改正。对手侧条栈止于咒力条。

### 3.3.1 咒力条为什么放在顶部（v0.2 修订）

初版把咒力与行动资源一起放在下中，实测读不到。查了同类作品的官方 HUD 说明后改为**上移至 P1 生命条正下方**，最终按 v0.3 收为**420×14 的窄条**（比生命条窄 25%、细 30%），与生命条形成明确主次而非两条等权：

| [饿狼传说 City of the Wolves](https://snk-corp.co.jp/webmanual/fatalfury-cotw/screen/?lang=en-US) | 血条与 S.P.G. Zone 在中上方，Power Gauge 与 REV Meter 在底部 | 官方手册逐项标注 |

#### 火影 HUD 的实测核对

文字说明取自[游侠网界面教程](https://gl.ali213.net/html/2016-2/107091_3.html)（原文：屏幕上方绿色长条为体力量表……血槽下方的蓝槽是查克拉量表……查克拉量表下方的四道横杠就是替身术的使用次数），并与同页实机截图（`Saved/ref/nuns4-interface.jpg` 及其 4 倍放大）逐项核对：

| 观察项 | 实机所见 |
| --- | --- |
| 整体形态 | 极扁、极薄，宽度约占屏幕 2/3，不给画面造成压迫 |
| 头像 | 带边框的方形角色立绘在**最左端**，紧贴条的起点 |
| 角色名 | 在条的**上方**，小字 |
| 生命条 | 最上层，细长亮色 |
| 查克拉条 | **紧贴生命条正下方，无间隙**，更细，蓝色 |
| 替身术计数 | 查克拉条**正下方 4 个离散暗色小格**，与条同宽，不额外占行 |
| 系统提示 | 出现在画面中部，不塞进条组 |

**对本项目的三条直接结论**：①咒力条必须与生命条贴合，中间不留间隙；②离散资源格（本项目的行动资源）应贴在条组正下方同宽排列，不单独占一行；③条组要有头像位，否则只是一组浮在角落的数字条。

关键在于**镜头类型决定底部是不是"顺眼区"**：传统格斗是固定侧视镜头，人物与对手稳定占据画面中部，底部气槽落在结构化的余光区，抬头看血条本来就是习惯动作；本项目是自由第三人称镜头，视线焦点在准星与对手身上，底部对玩家属于弱注意区。

再叠加一条本项目特有的理由：**咒力与行动资源的使用节奏不同**。行动资源是"闪避/取消时读一次"的整数决策，放在底部可以；咒力是**每次开炮前都要现查的弹药量**，还会自动回气（停炮 2s 后 +6/s）、近战命中额外 +3，属于持续波动的状态量。它与生命同属"我现在还剩多少本钱"，放在同一个扫描区更合理。

因此咒力上移后做了三处强化，让它值得占用顶部空间：

1. 条体加深填充并加外发光，与生命条形成主次而非并列关系；
2. 加 **8 咒力门槛刻度**：普通炮最低成本是 8，低于它直接无法起手，这条刻度把"还能不能开炮"变成一眼可判；
3. 加**状态点**（`回气中 +6/s` / `命中回气 +3` / `已满`），咒力 <8 时整条呼吸告警并提示"无法开炮"。

**领域能量没有再补一条**：v5.0 起它由右下大招按钮的充能环表达（见 §3.2）。代价是对手的领域能量连续进度不再可见，这条取舍见 §3.2 与设计板 03·e。

咒力的**数值语义与绑定关系完全不变**，只改落位与读数强化。

#### 图标视觉语言（v0.4 占位稿）

图标从**角色自身的美术母题**取形，而不是通用格斗符号。母题取自[官方角色图](assets/ishigori-official-20260322.jpg)：

| 母题 | 在角色图上的依据 | 图标中的用法 |
| --- | --- | --- |
| 高耸飞机头（两侧剃短） | 造型最突出的识别特征 | 近战图标底部的**上扬刘海弧** |
| 毛领 / 袖口尖齿毛边 | 浅色毛领与袖口 | 重击类的**单道尖齿三角**（"重"的记号） |
| 方形金属腰带扣 | 腰带正中带红纹的方扣 | 瞄准图标的**方框十字** |

**实施教训（已写进图标规范）**：v0.4 首版把飞机头、毛领、腰带扣三个母题同时塞进一个 30px 图标，结果重拳糊成一团、切形态外圈尖齿变成噪点、重踢的尖齿碎掉。**每个图标只承载 1–2 个母题**，重击类靠体量与线数区分"重"，不靠堆装饰。这一版是先简化到可读，正式的图标美术仍待细化（见 §8 待确认事项）。



### 3.5 蓄力炮组件（两套候选）

放在下中偏下的圆盘区，共享同一套状态色，原型里可按键切换对比：

- **方案 A 扇形能量环**：270° 环从底端顺时针填充，1.2s（普通炮）/ 2.4s（超级炮）封顶，封顶转金并出现向内收束短线。
- **方案 B 凝聚球 + 8 段刻度**：中心发光球随蓄力膨胀，外圈刻度按蓄力点亮，更贴近"咒力凝聚"的意象。

两套都必须能表现三种状态，其中第三种是本稿相对当前 HUD 的关键增量：

| 状态 | 表现 | 依据 |
| --- | --- | --- |
| 蓄力中 | 显示当前预计伤害，如 `伤害 62` | `30+60q` / `150+70q` |
| 已满蓄 | 金色 + `满蓄 90` + `松开才发射` | [08](08_石流龙战斗系统设计.md) §6.1：满蓄不自动发射 |
| **强度受限** | 已点亮部分实色，超出支付能力的部分为红橙虚线轮廓 + `咒力不足 · 强度上限 60` | `qPaid=clamp((已付成本-8)/16,0,1)` |

第三种的必要性：规则上伤害由**已支付成本**封顶（只剩 16 咒力时普通炮最高只能到 60，继续持炮不会变强，见 SLL-T17）。如果没有这个提示，玩家会持续持炮等待一个永远不会到来的强化，这属于"界面隐瞒了规则"。同时它也区分了 `已满蓄` 与 `咒力不足，强度受限` 两种不同含义（[08](08_石流龙战斗系统设计.md) §6.3 原文要求"HUD 区分'已满蓄'和'咒力不足，强度受限'"）。

主读数写成 `强度上限 60`，**不要补 `/ 100` 之类的满值刻度**：普通炮伤害区间是 30→90、成本区间是 8→24，两者都没有 100 的基准，凭空加一个百分比分母会让读数失去可核对性。受限态在任意持炮时长下读数都应恒为上限值（先升到上限后锁死），不得中途出现更低的数字。

超级炮另加 10 秒冷却环，在**发射或已付费中断**时启动（[08](08_石流龙战斗系统设计.md) §6.3、SLL-T20）；冷却中 Q 图标变灰。

**落位（概念稿阶段修正）**：蓄力进度不另起一个悬浮仪表，而是做成**围绕形态圆盘的外环**。理由是下中聚类已经很密（行动资源 / 形态圆盘 / 咒力 / 技能提示条依次排开），再插一个独立圆盘会同时压住角色腿部轮廓与技能提示条；绕在形态圆盘外圈既保持聚类紧凑，也顺带把"正在为哪个形态蓄力"这层意思表达出来。原方案"圆盘上方独立仪表"废弃。

### 3.7 训练信息与结果层

- 顶部模式徽标：`静止木桩 / 固定防御 / AI 对战`（`EOpponentMode`）+ 训练开关标签 `无限生命 / 无限资源 / 无冷却`。

**三条资源必须在色相上分开**（v5.0 改定）。v4.0 的生命条与咒力条都是冷白/青蓝系且零间隙相邻，只靠明度差读不出哪条是哪条。现按用户要求改为 **生命=橙 / 咒力=深蓝 / 行动=金**，实算色相分离：

| 对比 | ΔHue | 其他 |
| --- | --- | --- |
| 生命 28.8° ↔ 行动 41.2° | 12.4° | OKLab ΔE 0.111（≈5.5 JND）、ΔL 0.069 |
| 生命 ↔ 咒力 223.5° | 194.7° | — |
| 咒力 223.5° ↔ 领域能量 190.9° | 32.6° | 明度差 0.339，不会混 |

橙与金色相偏近（这是取色时发现的真问题：火影体力条的橙若直接取用会落到 hue 49°，与行动金几乎同色相），因此生命条取该暖色族的**琥珀端再向橙推**，落到 hue 24–36°；并补三重区分：**中间隔着 11px 的深蓝咒力条**（橙金从不接触）、体量与材质不同（500×15 带光刃的管体 vs 500×9 哑光标尺条）、明度差。若美术期仍觉得近，下一步应把生命条再向红推（hue≈22°），而不是继续压暗行动金（会伤到 5 格刻度的可读性）。

**"金"的用途已收窄**（v5.0）：不再表示"大招可用"（改由浅青蓝环 + 外溢表达），现在只剩两个瞬时用途——领域展开期的结界名与三发刻度、蓄力炮满。环境金紫与 HUD 金不冲突：环境色相偏移的作用域只覆盖 `#arena` 的穹顶/石台/角色，**碰不到 HUD 层**。

生命条填充不再使用冷白青渐变（v4.0 及以前）而改用橙色，是用户明确要求（对齐火影的体力条）。身份色仍只承担"这是谁"的识别，不承担"有多少"的读数。领域主色从 [领域概念图](assets/ishigori-domain-concept-v1.png) 提取后再实测，按 [08](08_石流龙战斗系统设计.md) §2 的美术分层要求，地面保持可读、不堆满爆炸与烟雾。

概念稿另附 OKLch 派生值用于生成透明度与衍生色，实现时以 Hex 为权威值。

### 4.1 视觉硬规则

1. **切角，不圆角**：结构面统一 8px `clip-path` 斜切（小控件 6px）。斜边要保留描边，需用"外层 1px 底 + 内层 1px 内缩同形切角"两层实现，不能只靠单层 border（斜边会缺线）。
2. **身份色只出现在名条与描边上**：生命条填充两侧统一。
3. **一个高价值色**：金紫只在领域满值/展开期出现，每屏不超过两次，避免弱化它的信号强度。
4. **信息密度分层**：常驻读数一律低对比，只有状态跃迁（受伤、满蓄、领域、压制）允许提亮放大，且全部 ≤350ms。
5. **擂台永远优先**：中央只保留准星与飘字，**任何面板不得跨越 1920×1080 的中轴线以下 1/3 的中心区**。这条同时约束底部聚类：蓄力组件与技能提示条必须在资源弧座之上逐层排开，不得侵入中央。


字体：数字用重体无衬线 + `tabular-nums`（数值跳动时不抖位）；中文标签用系统黑体；领域大字用拉字距的衬线体表现结界名质感。

## 5. 动效规格

| 事件 | 时长 | 缓动 |

## 8. 待确认事项

1. 蓄力组件最终选 A（扇形环）还是 B（凝聚球），需要在实机上看移速 55% 时的余光可读性。
2. 大招充能环与满能量外溢用自绘 Slate 还是材质/粒子，取决于后续是否接入正式美术的烟火材质。
3. 对手是否永久只显示生命 + 领域能量；若后续接入观战/回放需求，需要重新讨论对手资源层。
4. 生命条斜切角度与高度需在道场暗色环境（[11](11_日式道场场景接入说明.md)）里复核对比度，避免暗背景吞掉描边。
5. **技能图标是 v0.4 占位稿，待正式美术细化。** 母题选择（飞机头 / 毛领 / 腰带扣 / 头部炮击）已确定，但每个图标当前只承载 1–2 个母题以保证 30px 下可读。正式稿应在保持可读的前提下提高母题的辨识度，并补齐近战/远程两套共 9 个图标的统一节奏。
