# 石流龙接入：不用 Blender 的简化路径

版本：v0.1（方案，未开工）；日期：2026-09-20。

本文回答一个具体问题：**不会用 Blender，怎么做完"AI 模型 → UE 里替换默认角色"？**

结论先说：**可以跳过 Blender，但不是"全 AI"——而是把手工活从"建模软件"搬到"UE 编辑器点点点 + 我写脚本"。** 后者的门槛低得多，而且更好回退。

---

## 1. 为什么可以跳过 Blender

Blender 在标准流程里承担三件事：重拓扑、绑骨蒙皮、导出 FBX。这三件事各自都有替代：

| Blender 里的活 | 不打开 Blender 的替代 | 代价 |
| --- | --- | --- |
| 重拓扑 / 减面 | **生成时就直接要求低面数**（Tripo 面数滑块拖到 8–15 万）；UE 侧还有骨骼网格体 LOD 与减面工具（[Skeletal Mesh LODs](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/skeletal-mesh-lods-in-unreal-engine)、[Skeletal Mesh Reduction](https://dev.epicgames.com/documentation/unreal-engine/skeletal-mesh-reduction-overview)） | 布线不会漂亮，但没有特殊骨骼需求时够用 |
| 绑骨蒙皮 | **Tripo 自带自动绑骨**（消耗积分类似 10–20 一次），或 **AccuRig 免费自动绑骨** | 权重质量不如手工，腋下/胯部可能穿帮 |
| 动画重定向 | **UE 自带 Auto Retargeting**（[官方文档](https://dev.epicgames.com/documentation/unreal-engine/auto-retargeting-in-unreal-engine)），右键动画 → 重定向，选源骨架和目标骨架，自动生成重定向器 | 脚滑、手部扭曲需要微调，但通常能出可玩结果 |
| 导出 FBX | Tripo 直接导出 FBX | 无 |

**更关键的一点**：本工程已经有 `Scripts/ue_python.py` + `Scripts/ue_mcp.py`，能通过 UE 的 Python 远程执行和 MCP 在**编辑器里直接建资产、改属性、批处理**。所以"重复性的编辑器操作"可以由脚本完成，你只需要在关键节点用眼睛验收。

## 2. 先把预期说清楚：AI 到不了的地方

| 能做到（AI/脚本） | 做不到（必须人判断或接受妥协） |
| --- | --- |
| 出一个比例、轮廓可用的网格 | 拓扑布线（关节循环边）——**不做也不影响 Demo 跑起来**，只影响以后做新动作 |
| 自动绑出一套人形骨架 | 蒙皮权重完美（抬臂时的腋下、深蹲时的胯） |
| 复用工程里现有的 131 段动画 | **动画通知会丢**——重定向后的序列没有攻击窗口通知（见 §7，这是唯一必须改代码的地方） |
| 自动生成物理资产、LOD | 头发/毛领的物理摆动（建议先放弃，见 §6） |
| 一键替换网格、校准 Socket | 手感微调（脚滑、滑步距离、打击感） |

**最重要的一条认知**：你工程里的战斗手感**来自动画时间轴和命中窗口，不是来自网格**。所以换上石流龙的皮、继续用 Manny 的骨架和现有 131 段动画 + 已调好的蒙太奇，**手感不会退化**。等哪天要为他做专属招式，再考虑回 Blender 或 Cascadeur。

## 3. 路径 A：全在 Tripo + UE 里做（推荐）

### 第 1 步：Tripo 生成（已完成大半）

按 [15a](15a_石流龙三视图提示词.md) 出图 → 多视图槽位 `前/左侧/右侧/后`（右侧由左侧镜像）→ 生成设置见下表。

**Tripo v3.1 生成设置（实测截图确认）**：

| 选项 | 选什么 | 说明 |
| --- | --- | --- |
| 模型版本 | **v3.1 高精度模型**（已选） | 面数上限 50,000，**滑块拉满即可**（所谓 2,000,000 是显示上限，v3.1 实际封顶 5 万） |
| 超清几何精度 | **开**（已开） | 唯一不可回退的环节，别省 |
| **纹理生成** | **开** ⚠️ | 截图里是关闭状态。关了导出的就是灰模，进 UE 没有颜色 |
| 分部件生成 | **开**（有 1 次试用） | 按语义自动把外套/头发/毛领/身体分开，方便后面单独调材质或加物理 |
| 8K 贴图 | 可选（有 1 次试用） | 4K 已够；试用机会可以留给另一版 |
| 拓扑 | 开 + **三角面**（已选） | 四边面上限只有 2.5 万，三角面能到 5 万，且 UE 内部本来就是三角面 |

⚠️ **多视图槽位**：四个槽必须都有图，否则会提示"请补全四个视图"。**右侧槽用左侧图水平镜像后上传**（见 [15a §3.4](15a_石流龙三视图提示词.md)），不要重新生成——两张分别生成的侧面厚度对不上，会把模型带歪。

### 第 2 步：Tripo 自动绑骨

在模型详情里找**绑骨/骨骼（Rigging）**入口，选**人形（Humanoid）**模式：

- 有 T-pose / A-pose 选项就选 **A-pose**（和 UE5 Manny 的参考姿势一致，重定向更准）
- 绑完**务必自己验证**：在 Tripo 预览里让它做抬臂、抬腿、转身，看腋下、胯部、脖子有没有明显破面
- 不合格就重绑；Tripo 的绑骨是独立收费项（十几积分），比返工便宜

> ⚠️ **待实测项**：Tripo 自动绑骨导出的**骨骼命名**是它自己的规则还是标准人形命名，目前没有可靠资料（其开发者文档页本次抓取失败）。这**不影响能不能用**——UE 的 Auto Retargeting 会自动做骨骼映射，命名不同也能对上；只影响"能不能一次映射准"。

### 第 3 步：导出 FBX

格式选 **FBX**（带骨骼的这一步不要用 GLB，UE 的原生骨骼管线吃 FBX 最稳）。贴图一并要。

### 第 4 步：UE 导入

1. 把 FBX 拖进 Content Browser，放在 `Content/Characters/Ishigori/`（新建目录，别混进 `Mannequins/`）
2. 导入选项：勾 **Skeletal Mesh**、**Import Mesh**；Skeleton 选 **None（新建）**——它会自动创建一套与 Tripo 骨架对应的 Skeleton
3. 导入后双击打开网格，量身高：**期望 190 左右**。差得离谱就在导入时改 Import Uniform Scale（比如整体小 100 倍就是单位问题）
4. 检查有没有贴图、材质槽是否合理

### 第 5 步：让 131 段动画变成它的动画（Auto Retargeting）

这是整条路径的关键一步，全在编辑器里点，不需要 Blender：

1. 在 Content Browser 找到任意一段现有动画（例如 `Content/Characters/Mannequins/Anims/Unarmed/` 下的走路或待机）
2. **右键 → Retarget Anim Assets → Duplicate Anim Assets and Retarget**
3. 源骨架 = `SK_Mannequin`；**目标骨架 = 新导入的石流龙骨架**
4. UE 会自动创建 IK Rig / IK Retargeter 并自动映射骨骼链
5. 在预览窗口里逐段看：**先看走路和待机**，脚有没有悬空/陷地、手有没有扭成麻花
6. 满意 → 导出；不满意 → 在自动生成的 IK Retargeter 里调链映射（通常只需调 Spine/Pelvis 的高度与地面约束）

批量做法：在多选动画的状态下重定向，一次处理一批。

### 第 6 步：替换 + 校准（我可以用脚本做）

| 项 | 操作 |
| --- | --- |
| `BP_Fighter` 换网格 | 蓝图 → Mesh 组件 → Skeletal Mesh 换成新的；Anim Class 指向重定向后/新建的 AnimBP |
| `Muzzle_Head_Review` Socket | 打开新骨架的 Skeleton 编辑器 → 在 `head` 骨骼上添加 Socket，**名字必须叫 `Muzzle_Head_Review`**，位置调到额头/发际线附近 |
| `hand_r` 命中检测点 | 骨架里确认 `hand_r` 存在；不存在就按 Tripo 的手部骨骼名创建 Socket 并改名，或在 `AttackDefinition` 里改 TraceSocket |
| Capsule / 相机偏移 | 按新模型身高复核（`FighterDefinition.h` 里的 `AimSocketOffsetY/Z` 等） |
| HUD 位置 | 跑一遍 PIE，看 `M_FighterTint` 双方标记和 HUD 有没有被模型挡住 |

### 第 7 步：验收

跑现有脚本：`python Scripts/run_m6_acceptance.py`、`run_m7_A_acceptance.py`（炮口遮挡那套）、`run_dojo_smoke.py`。**炮口贴墙检测必测**——它直接吃 Socket 位置。

## 4. 路径 B：我写自动化脚本，你只做验收（更省事）

工程已经具备条件（`Scripts/ue_python.py` 通过 UE 的 Python 远程执行驱动编辑器，`ue_mcp.py` 提供 MCP 调用）。可以写一套 `Scripts/M8_art_swap.py`：

- 按固定路径把 FBX 导入并落到 `/Game/Characters/Ishigori/`
- 自动创建 Skeleton 的 Socket（`Muzzle_Head_Review`、手部检测点）
- 批量重定向指定动画集到新骨架
- 批量重建蒙太奇（复制原蒙太奇、替换里面引用的动画序列）
- 把 `BP_Fighter` 的 Mesh 与 Anim Class 指过去
- 输出一份 JSON/日志：身高、面数、Socket 列表、重定向结果、失败项

**你只需要**：把 FBX 放到指定目录 → 说一声 → 看脚本输出 → 打开编辑器 PIE 看效果。

这条路我需要你确认后才能开工（因为要动 `BP_Fighter` 和新建资产），风险是脚本一次性改的资产较多，所以会分步执行、每步留可回退记录。

## 5. 面数不够理想时的处理（全在 UE 里）

1. **首选**：回到 Tripo 重生成，面数滑块直接定到 8–15 万
2. **次选**：导入后打开 Skeletal Mesh 编辑器 → **LOD Settings / Reduction**，用引擎自带的减面生成 LOD1/LOD2。注意这只影响远处显示，LOD0 还是高模
3. **终选**：如果面数在百万级、编辑器卡到没法用，说明必须重生成——**别硬扛**

包体与性能预期：4–6 万三角面 + 4K 贴图的单角色，对这个 Demo 是可接受的；百万面则会让 Cook 时间和包体明显膨胀，也会拉低帧率（工程当前编辑器约 39–41 FPS 的基线已经很紧）。

## 6. 建议放弃/延后的部分

| 项 | 建议 |
| --- | --- |
| 头发、毛领的物理摆动 | **先放弃**。物理资产调不好会抖、会穿模，且飞机头这种大幅摆动最容易翻车。先用刚性网格，等基础接入跑通再考虑 |
| 手指精细动作 | 放弃。现有动画不需要独立手指骨骼，Tripo 自动绑骨给的手指数也未必够 |
| 面部表情 / 口型 | 放弃。本工程没有面部动画需求 |
| 专属招式动作（结印、领域展开姿势） | 延后。等接入跑通，再用 Cascadeur 之类做少量姿势 |

## 7. 唯一躲不掉的一处改动：动画通知

重定向生成的是**新的动画序列**，原来的**动画通知（Anim Notify）不会跟着过来**。而本工程的攻击命中窗口是"**优先由动画通知驱动，无通知时回退时间窗口**"（见 `AttackDefinition.h`）。

所以有两条路：

- **A（推荐，不改代码）**：把攻击定义的 `bWindowFromAnimNotifies` 设为 **false**，走时间窗口回退。手感会略钝一点，但立刻能打
- **B（更好，要改资产）**：在重定向后的动画序列上，用 UE 的动画编辑器重新插入 `AttackWindowOpen/Close` 通知。**这个操作可以在 UE 里做，不需要 Blender**，只是要逐段对齐帧

另外蒙太奇也要重建：重定向工具只处理动画序列，**蒙太奇必须新建**（在 UE 里右键新建 Montage、挂上动画序列即可，也能脚本批处理）。

## 8. 如果连"重定向调参"也不想碰

那就只剩一条更省事的路线：**直接找现成的 Manny 骨架模型**。

- Epic 官方的 **MetaHuman**、Fab 上的角色包，很多直接给 Manny/UE5 骨架版本——**导入就能用全部 131 段动画，连重定向都不需要**
- 代价：外观不是石流龙，是"另一个角色"
- 但作为**阶段性替代**很有价值：先用一个"有脸有衣服的真人角色"把整个接入链路（Socket、炮口、HUD、验收、打包）跑通一次，再拿石流龙走同一条已验证的链路

**这条路线我建议作为兜底**：万一 Tripo 的绑骨质量实在不行，不至于卡死。

## 10. 实测记录：Tripo v3.1 走通的坑

以下为本次实际操作中真实发生的问题与结论，按发生顺序记录。

| # | 现象 | 原因 | 结论 |
| --- | --- | --- | --- |
| T1 | 正视图头顶鼓成**两个圆包**、中间凹一道沟 | 提示词里"后脑：发量**层层向后堆叠**"被模型理解为把头发分成两瓣 | 提示词必须写成"**一整块连续实心体积**"并列出禁止项（见 [15a §3.1](15a_石流龙三视图提示词.md)） |
| T2 | 多视图界面提示"请补全四个视图" | 右侧槽为空。**右侧不要重新生成** | 左侧图**水平镜像**后上传（[15a §3.4](15a_石流龙三视图提示词.md)） |
| T3 | 生成出**灰模**无颜色 | 「纹理生成」开关默认关闭 | 生成阶段就要把**纹理生成打开**；也可以事后单独补一次「纹理生成」 |
| T4 | 勾选「**分部件生成**」+ 自动绑骨后，头、单只靴子、一片毛领**飞离身体**，袖子糊成一团 | 分部件把头发/毛领/外套/靴子拆成独立部件，自动绑骨时**部分部件没被赋权重**，随子物体变换甩出 | **「分部件生成」与「自动绑骨」当前不兼容**。要绑骨就**关掉分部件生成**；关掉后重绑即恢复正常（实测已复现并解决） |
| T5 | v3.1 面数上限 | 滑块显示上限 2000000，但 v3.1 实际 50000；多视图模式下输出会更多（实测输出 **144,854 三角面**） | 14.5 万面对 UE 完全可用，不必追求更低 |

### 10.1 绑定这一步的正确顺序（实测有效）

1. 左侧菜单「绑定」→ 绑定类型 **人形**
2. **骨骼预设选 `UE5 Mannequin`** —— 这是整条流程最关键的一次选择，直接决定 131 段动画要不要重定向
3. 点「自动绑定」（约 20 积分）
4. **验证**：让角色抬臂、抬腿、转身、深蹲，重点看**腋下 / 胯部 / 脖子**是否破面
5. 通过后再「导出」FBX

> ⚠️ **待实测**：Tripo 的 "UE5 Mannequin" 预设究竟是"完全照抄 Epic 骨架命名与层级"，还是"比例对齐但用自己的命名"，官方文档未说明清楚。导出的 FBX 用 `Scripts/M8_ishigori_art_check.py` 一验便知。

### 10.2 接入前验证脚本（已就绪，未运行）

`Scripts/M8_ishigori_art_check.py`：

- 只读 `AssetArchives/Ishigori_AI/03_rigged/*.fbx`，只写 `/Game/Training/ArtReview/`（已 gitignore，可重建）
- **不碰** `BP_Fighter`、`DA_Fighter_Ishigori`、任何现有动画或地图
- 输出 `Docs/开发过程/验收记录/M8_ArtCheck.json`：骨骼全列表、与 Manny 核心骨的**逐项比对**、身高、材质槽、贴图清单、结论与阻塞项
