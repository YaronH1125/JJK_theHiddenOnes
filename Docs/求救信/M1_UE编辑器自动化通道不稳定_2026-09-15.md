## 3. 卡点（需要帮助的核心问题）

### 卡点 1：编辑器控制台 `py` 命令执行通道不可靠

现象：
- 通过桌面自动化点击 Cmd 输入框 → `type` 文本 → 回车，**时灵时不灵**；
- 多次尝试后输入框内文本**累加**（两次输入内容拼接，中间出现乱字符如 "vvv"）；
- `Ctrl+A` 全选替换在该 Slate 输入框中似乎不生效（替换后仍是旧文本拼接）；
- 判断原因：编辑器与用户正在使用的其他窗口**争夺前台焦点**，键入的字符流被拆散/丢失；此外该输入框属于编辑器主窗口底部 Dock 区，点击命中有时被任务栏边缘的一个透明窗口截获（Windows）。

已尝试：
- SlateInspectorToolset（UE-MCP 的 Slate 自动化工具，用 ProcessKeyCharEvent 直接注入，不需要前台）：对输入框 `Type("hello")` 返回 true 且成功；但 **`PressKey(ref, "Enter")` 返回 true 却不触发命令提交**（命令从未执行，LogPython 无任何新输出）。
- 用 SlateInspector Snapshot/Observe 找到输入框 widget ref（textbox [ref=tb1]）确认其 `[focused]` 状态。

问题 1a：UE 的输出日志控制台输入框（SLate SEditableTextBox + 命令提交回调），用 Slate 事件注入（ProcessKeyDownEvent 发 Enter/Enter 键名）为什么不触发提交？正确的模拟提交方式是什么？
问题 1b：有没有比"控制台输 py 命令"更稳的编辑器内 Python 执行入口（不占用前台焦点、可从命令行触发）？例如：UE-MCP 里是否有我漏掉的 exec/python 工具？或者可以用某种"文件监听 + 编辑器内已注册的回调"模式？
问题 1c（备选方案评估）：**关闭编辑器后用 `UnrealEditor-Cmd.exe <uproject> -run=pythonscript -script=xxx.py` 执行资产/关卡操作**是否可靠？已知顾虑：世界上下文、EditorLevelLibrary 在 commandlet 下是否可用、保存 umap 是否完整。用于"资产创建/CDO 配置/关卡修改"这类非实时操作是否是社区标准做法？

### 卡点 2：Python 修改蓝图 CDO 后，同一次编辑器会话内的 PIE 读到旧值

现象（时序）：
1. 编辑器内 Python 创建 BP_TrainingGameMode（父类 ATrainingGameMode，C++ 侧有 `FighterClass` 等新 UPROPERTY）；
2. `unreal.get_default_object(bp.generated_class()).set_editor_property("fighter_class", ...)` 设置成功（无异常）；
3. `unreal.EditorAssetLibrary.save_asset("/Game/Training/BP_TrainingGameMode.BP_TrainingGameMode")`（注意当时传的是**带对象名**的路径而非包路径）；
4. 同一会话立即 PIE：GameMode 实例 `fighter_class == None`，日志报"未配置 FighterClass"；
5. **重启编辑器后**，用 MCP 读同一 CDO（`/Game/Training/BP_TrainingGameMode.Default__BP_TrainingGameMode_C`）属性值**存在且正确**，PIE 也正常。

推断：save_asset 触发了蓝图编译，编译用 Blueprint 资产内序列化的旧 CDO 数据**重建/还原了内存中的 CDO**，导致"磁盘是新的、内存是旧的"，直到重启编辑器。

问题 2a：这个推断对吗？UE5 中用 Python 给蓝图生成的类的 CDO 设置属性并立即对 PIE 生效的**标准做法**是什么？（例如：先改 CDO 再 `unreal.EditorAssetLibrary.save_loaded_asset(bp, only_if_is_dirty=false)`？还是应该改 `bp.get_editor_property('...')`？还是必须 `unreal.BlueprintEditorLibrary` 某接口？）
问题 2b：`save_asset` 传"对象路径"（含对象名）与"包路径"行为差异？是否会静默失败？
问题 2c：如何让 set_editor_property 后的 CDO 修改被蓝图资产正确序列化（dirty 标记链路）？

### 卡点 3：ZCode 的 unreal-mcp 客户端在编辑器重启后无法恢复

现象：UE MCP 服务器（编辑器进程内 HTTP，127.0.0.1:8000/mcp，Streamable HTTP 传输）随编辑器重启后会话表清空；ZCode 的 MCP 客户端缓存旧 `Mcp-Session-Id` 继续请求，服务器返回 JSON-RPC 错误 `"Unknown session id ...; client should reinitialize"`，但客户端**不会自动重新 initialize**，之后所有 `mcp__unreal-mcp__*` 工具调用全部失败，直到重启 ZCode 会话。

当前绕行：我在 bash 里用 curl 手工完成 `initialize` + `notifications/initialized` + `tools/call`（带新 Mcp-Session-Id 头）直连编辑器服务器，功能完整可用。

## 附录 A：UE 5.8 API 变化备忘（相对 5.3/5.4 常见教程写法）

1. `AttributeSet.h` 不再定义 `ATTRIBUTE_ACCESSORS` 宏（只在注释里保留示例），改名为 `ATTRIBUTE_ACCESSORS_BASIC`。
2. `FGameplayEffectModCallbackData` 完整定义从 GameplayEffect.h 挪到 **GameplayEffectExtension.h**（两处都只有前置声明）。
3. `UAbilityTask` 头文件路径为 `Abilities/Tasks/AbilityTask.h`（旧教程常写 Abilities/GameplayTask.h，5.8 不存在）。
4. `DEFINE_LOG_CATEGORY(X);` 需要分号，且定义所在 .cpp 必须包含声明它的头（否则 FLogCategoryX 类型未定义）；此前未被引用时链接器不报错，一旦被引用即 LNK2001。
5. UHT：UPROPERTY 不能命名 `Role`（与 AActor::Role 冲突，shadowing 不允许）。
6. Python：`MaterialEditingLibrary` 在 5.8 没有 `set_material_property`（无法用 Python 设置材质 BlendMode/Opacity 标量属性，改用节点连接 BaseColor 方案绕过）。
