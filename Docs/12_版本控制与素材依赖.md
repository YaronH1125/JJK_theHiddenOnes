## 新机器恢复

**仅 clone 仓库不会获得完整道场和 EnergyBeam；恢复以下依赖后再打开默认地图或打包。** 素材归档通过已有素材库或私有交接渠道取得，Git 不备份被忽略的文件。

1. 获取与清单匹配的 `Mishima_DOJO.zip` 和 `EnergyBeam.zip`。本机独立归档位于 `AssetArchives/<时间戳>/`，同目录 `archives.json` 保存归档 SHA-256；ZIP 已检查 CRC。归档与工作副本同盘，不等于异地备份。
2. 解压到项目根目录。ZIP 中已包含 `Content/Mishima_DOJO/...` 与 `Content/EnergyBeam/...`，避免重复套一层 Content。不要重命名或移动 UE 资源路径。
3. 使用 Python 3.11+ 运行 `python Scripts/check_external_assets.py`。两包均应 PASS；缺失、增加或内容改变会返回非零。结果写入本地 `Saved/External_asset_integrity.json`。
4. 使用 UE 5.8.2 构建 `Development Editor`，打开项目，进入 `L_DojoArena` 播放；F1 打开训练面板。白盒仍为 `L_TrainingArena`。
5. 关闭本项目编辑器后运行 `Scripts/build_dojo.ps1`。脚本会先核对原素材文件是否存在及大小；需要精确版本校验时执行上面的 SHA-256 检查。`-ReuseCook` 仅用于已存在、与当前资产一致的 Cook 产物，首次构建不要使用。

独立包位于 `Saved/Packages/Dojo/Windows`，直接双击顶层 `JJK_theHiddenOnes.exe`。复制给测试者时必须复制整个 Windows 目录，不能只复制 exe。

## 提交方式

- 先看 `git status`、`git diff` 和 `git diff --cached`，按明确文件列表暂存，避免 `git add .` 混入原素材与临时结果。
- 使用 `type(scope): 中文说明`，本次按 `chore(repo)`、`feat(dojo)`、`test(dojo)`、`docs(demo)` 分组；同组包含相互依赖的源码与玩法资产。
- 提交正文记录具体变化、验证和未验证项。未重新执行的测试只能引用已核对快照的历史结果，不能宣称本次重跑。
- 二进制资产继续遵循 `.gitattributes`，禁止文本合并；不要因某个素材包很大就全局忽略 `*.uasset` 或 `*.umap`。
- 提交后确认工作区干净、原素材仍在本地、忽略规则命中正确。`commit` 与 `push` 分开；本次仅本地提交。
