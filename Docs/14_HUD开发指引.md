## 1. 要做什么

在现有单机 1v1 训练擂台 Demo 上，新增一层**正式战斗 HUD**，替换当前开发用 UI。

| 项 | 决定 |
| --- | --- |
| 引擎 | UE 5.8.2 |
| 画布基准 | **1920×1080**，等比缩放适配 |
| 技术栈 | UMG（UMG + Slate 自绘混用，见 §5.3） |
| 与现有 UI 的关系 | **新建独立 Widget，不修改已通过回归的调试层**（见 §8.1） |
| 目标平台 | PC 键鼠单机 |

**本版定义三个视觉分区**：资源在左右上角、技能在右下、操作反馈在中下。这是与"双方顶部大血条"式格斗 HUD 的主要区别——本项目是自由第三人称视角，视线焦点在准星与对手身上。

### 3.2 P2 身份与资源（右上）

镜像：`right:32px; top:28px`，`flex-direction:row-reverse`，条栈内文字右对齐，条体多边形水平翻转，填充从右向左。**止于咒力条，没有行动点行**——所以 P2 条栈比 P1 矮约 21px。

### 3.3 行动点（5 个菱形豆）

| 项 | 值 | 依据 |
| --- | --- | --- |
| 数量 | **5** | `FighterDefinition.h`：`MaxActionResource = 5` |
| 消耗 | 普通闪避 **1**、取消攻击的闪避 **2**（总计，不是 1+2） | `DodgeCost = 1`、`CancelDodgeTotalCost = 2` |
| 恢复 | 停止消耗 1 秒后每秒 +1 | 起测值，待调 |
| 表现 | 满豆 / 空豆两态；**必须能表现"扣 2 点"**（同时暗两个） | 见下 |

**为什么是 5 个菱形豆而不是 5 个方块**：点数存在 **2 点一次**的消耗，做成 5 个等宽槽位会暗示"一格一次"。菱形豆是离散点，可以任意组合暗掉几个，天然表达扣 2。形制照火影的替身豆。

**尺寸待定**：豆的视觉尺寸当前取 **13×13**，这是按"豆高 ÷ 条高 = 1.65"反推的值。参考图（751 宽裁切）目视量得约 28×28，但那张图可能是放大特写，两者差 1.55 倍。**实现时请先用 13×13**，待确认参考图原始帧宽后再定（见 §10 待决项）。

### 3.4 技能区（右下）

| 槽位 | 圆心坐标 | 直径 | 键位标识 | 图标 |
| --- | --- | --- | --- | --- |
| **普攻** | (1460, 1004) | Ø70 | **鼠标左键图标** | 近战=拳击 / 远程=咒力炮 |
| **Q** | (1580, 1004) | Ø70 | 字母 `Q` | 近战=腿击 / 远程=超级炮 |
| **E** | (1700, 1004) | Ø70 | 字母 `E` | 切形态（拳⇄炮口） |
| **R 大招** | (1820, 1004) | **Ø96** | 字母 `R` | 领域展开 |

- **中心距一律 120px**（前三个等距，大招与 E 同为 120）。这个 120 是从参考图实测换算的。
- 大招 Ø96 = 普通技的 1.37 倍，且带**同心充能环**——它靠体量与环拉主次，不靠间距差。
- 键位标识压在按钮**下缘外**（`bottom:-9px`），高 15px。
- **只有键位标识，没有任何技能名文字**——这是明确的设计决定，识别靠图标，按键靠一个字母/图标。

**普攻与 Q 两格随形态整组换图标**，切换时两格同时换。

### 4.1 六级明度阶梯（v6.0 建立，不要回退）

**目标值写的是"渲染后 luma"，不是 alpha**——旧版把结构/描边/内容全挤在同一个 `.18` 透明度上（合成 luma 只差 8–27），四层在成片上分不开，这是"廉价感"的第一来源。

### 5.4 刷新频率（重要）

现有调试 HUD 用 **10Hz 定时器**刷新（`UCombatHudWidget` 里的 `SetTimer(..., .1f, true)`）。

**正式层不能沿用**：蓄力进度、领域倒计时、发炮刻度、生命虚血回落都要求逐帧或接近逐帧。做法：

- 数值类（生命/咒力/行动/领域能量）：可以按事件驱动（Attribute 变化时刷新）或 10–20Hz；
- **连续量（蓄力进度、倒计时、虚血回落、充能环、冷却扇形）：必须在 `NativeTick` 里按帧插值**，不要走定时器。

## 6. UI 状态 → 数据来源

**HUD 只读，不拥有任何战斗状态。**

| UI 元素 | 数据来源 |
| --- | --- |
| 生命 / 生命上限 | `Fighter->GetFighterAttributeSet()->GetHealth()` / `GetMaxHealth()` |
| 咒力 / 上限 | `GetCursedEnergy()` / `GetMaxCursedEnergy()` |
| 行动资源 / 上限 | `GetActionResource()` / `GetMaxActionResource()` |
| 领域能量 / 上限 | `GetEnergy()` / `GetMaxEnergy()` |
| 当前形态 | `AFighterCharacter::GetStance()` → `EFighterStance::Melee / Ranged` |
| 是否蓄力中 | `IsBlastCharging()` |
| 蓄力进度（0–1） | `GetBlastChargeAlpha()` |
| 是否瞄准 | `IsAimingEffective()` |
| 是否防御 | `IsGuarding()` / `IsGuardIntent()` |
| 是否闪避中 | `HasCombatTag(TAG_State_DodgeInvulnerable)` |
| 闪避成功反馈 | `HasRecentDodgeSuccess()` |
| 是否疾跑 | `IsSprinting()` |
| 是否攻击中 | `IsAttacking()` |
| 是否倒地 / 抓取 | `HasCombatTag(TAG_State_KnockedDown)` / `HasCombatTag(TAG_State_ThrowPaired)` |
| 是否死亡 | `IsDead()` |
| 领域是否展开 | `IsDomainActive()` |
| 对手模式 | `ATrainingGameMode::GetOpponentMode()`（经 `IsModeAvailable()` 判断可选项） |
| 比赛结果 | `GetMatchOutcome()` / `IsMatchResolved()` |
| 训练开关 | `Settings.bInfiniteHealth` / `bInfiniteResources` / `bNoCooldown` |
| 双方角色 | `GetPlayerFighter()` / `GetOpponentFighter()` |

**取值路径说明（重要，别写错）**：`GetHealth()` / `GetMaxHealth()` / `GetEnergy()` / `GetMaxEnergy()` / `GetMaxActionResource()` 等是由 `ATTRIBUTE_ACCESSORS_BASIC(UFighterAttributeSet, X)` 宏在 **`UFighterAttributeSet`** 上生成的，**不在 `AFighterCharacter` 上**。正确路径是先拿属性集：

```cpp
const UFighterAttributeSet* A = Fighter->GetFighterAttributeSet();
const float Hp = A ? A->GetHealth() : 0.f;
```

现有 `UCombatHudWidget.cpp` 就是这么取的，可以直接照抄口径。

`AFighterCharacter` 上**自带**的便捷获取器只有这几个：`GetActionResource()`、`GetCursedEnergy()`、`GetBlastChargeAlpha()`、`GetGuardFrontArcHalfAngle()`、`GetStatsInitCount()`，以及 `GetStance()`。其余都要经属性集。

**可用的 State Tag 全集**（拼错会静默失效）：`TAG_State_Attacking`、`TAG_State_BlastCharging`、`TAG_State_Dead`、`TAG_State_DodgeInvulnerable`、`TAG_State_DodgeRecovery`、`TAG_State_DomainActive`、`TAG_State_DomainCasting`、`TAG_State_GettingUp`、`TAG_State_Guarding`、`TAG_State_GuardStun`、`TAG_State_HitStun`、`TAG_State_KnockedDown`、`TAG_State_RangedBlastCharging`、`TAG_State_StanceSwitching`、`TAG_State_SuperArmor`、`TAG_State_SuperBlastCooldown`、`TAG_State_ThrowPaired`。

**蓄力强度（本项目最关键的一个读数）**：伤害由**已支付咒力**封顶，不是由蓄力时长单独决定。公式见 [08](08_石流龙战斗系统设计.md) §7.2：

```
q       = clamp(实际蓄力秒数 / 1.2, 0, 1)
已支付   = min(8 + 16q, 当前咒力)
qPaid   = clamp((已支付 - 8) / 16, 0, 1)
伤害     = 30 + 60 × qPaid          ← 普通炮
```

超级炮同理：`q = clamp((t-1.2)/1.2, 0, 1)`、`已支付 = min(45 + 20q, 咒力)`、`qPaid = clamp((已支付-45)/20,0,1)`、`伤害 = 150 + 70 × qPaid`。

**受限态**（`qPaid < q`）必须与"已满蓄"区分：已点亮部分实色，超出支付能力的部分用红橙虚线轮廓，读数写 `咒力不足 · 强度上限 60`，**且在任何持炮时长下都维持这个上限值、不出现更低的数字**。

## 8. 实现注意与已知坑

这一节是我们做概念稿时**实际踩到并修掉**的问题，实现时很容易重犯。

### 8.1 不要改调试层

现有 `UCombatHudWidget`（双方四资源数值 + 状态文本）与 `UTrainingPanelWidget`（F1 训练面板）**已通过回归**。正式层新建 `UArenaCombatHudWidget` 并存，通过开关切换（`bDebugHud` 已存在）。调试层继续承担"输入记录、当前能力、标签、动作窗口、命中轨迹、领域会话 ID、在途球数"。

### 8.2 三个"被祖先裁掉"的坑

我们三次踩到同一类问题——**光读 CSS/属性会以为是对的，实际元素根本没渲染出来**：

1. **条上的刻度放进了带 `clip-path` 的条体里** → 被裁掉。刻度必须是条体的**兄弟节点**。
2. **咒力条 8 点门槛刻度的"上下出头"部分放进了带 `overflow:hidden` 的层** → 出头部分与三角标记**从未渲染**。门槛要挂在不裁切的容器上。
3. **准星的 `left/top` 被写成负像素值**（本意是"以中心为原点"），而容器原点在左上角 → 五段全部落在容器外，**准星从来没画出来过**。正确做法是给线段加 `transform:translate(-50%,-50%)` 让 `left/top` 表示中心，或在计算时加上容器中心偏移。

**UMG 里的等价风险**：`Clip to Bounds`、`Retainer Box`、`Invalidation Box`、Render Transform 与父级裁剪的交互。任何"贴边/出头/居中"的元素，实现后**必须截图验证它在画面上真的存在**，不要只看属性。

### 8.3 填充几何

- 右锚定的条（P2 侧）填充宽度**按内层测量**，不要对外层算百分比——我们出过"P2 咒力 74% 显示为空条"的 bug（填充宽度算成整条）。
- 父级若是 `flex-end` 对齐，子元素会**收缩到内容宽度**；而填充是绝对定位时条体会塌成 0 宽。给条体显式 `width:100%`。
- **验收标准**：P2 咒力 74% 时，填充应位于条体**右段约 74% 宽度处**，右端对齐。

### 8.4 圆弧的零长度端点

`stroke-linecap:round` + `stroke-dasharray:0 100` 时，**零长度的 dash 仍会渲染出一个圆点**。我们在两处踩到（大招充能环、顶部领域弧槽）。处理：低于阈值时整条 `opacity:0`，并给基础 CSS 也设 `opacity:0` 防首帧闪烁。

### 8.5 静帧验证的限制

如果你们也用截图脚本做自动校验，注意：**导出管线会把 CSS 动画停在最后一帧**。凡是终态 `opacity:0` 的层（外扩环、粒子）在导出图里等于不存在，连输出字节数都不变。做视觉回归时要么让终态本身可见，要么显式触发。

### 8.6 10Hz 不够用

见 §5.4。连续量必须按帧。

- 概念稿是网页实现，**不是引擎截图**；实机观感（尤其领域展开期的环境偏移与 HUD 对比度）必须在道场暗色环境里复核一次，见 [11 日式道场场景接入说明](11_日式道场场景接入说明.md)。
- 本稿的数值全部是**调试参数**，不是平衡结论。
