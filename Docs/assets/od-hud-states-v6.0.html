01

设计说明

三条取舍的理由

A为什么双方能量条对称排布

照火影究极风暴4 的做法，把生命 → 咒力（紧贴）→ 行动资源条集中在两侧上角并左右镜像：咒力决定对手还能不能开炮，是玩家真正会读的对抗信息，所以对手侧同样给满。但行动资源是玩家自己的资源（躲闪消耗、1s 静止后每秒回 1），对手的行动点数不构成玩家可读的决策信息，因此这一行只在玩家侧。真正属于调试信息的（技能冷却、已支付咒力、领域会话、在途球数）留在调试层，不进主视野。

B为什么蓄力要显示强度上限

伤害与咒力是两个耦合变量：已支付咒力不足时，继续持炮不会提升伤害（仅剩 16 咒力时普通炮上限 60）。若不显式标出可支付区间，玩家会把“持炮更久”误当成“更强”。所以环上把超出支付能力的部分画成红橙虚线轮廓，读数直接锁在强度上限。

C为什么领域能量搬到大招环上（v5.0 改动）

原来顶部中央有一对弧槽分别显示双方领域能量。但领域能量的用途只有一个：告诉你 R 键能不能按。把它拆到屏幕顶部，玩家就得在"看对手"和"看自己能不能开大"之间来回扫视；而大招按钮本来就是回答这个问题的唯一位置。所以 v5.0 移除顶部弧槽，能量直接长在 R 键的环上——蓄了多少、满没满、能不能按，全在同一处。

代价（必读）：失去"同时看双方领域能量"的能力。原设计里双领域压制需要同时读两边，现在对手的领域能量百分比在 HUD 上不可见。替代表达见 03·e 取舍说明。

03·b

条组材质（v2 升级手法）

层次不变，只换表面处理；每一层都是"外描边 → 深色内槽 → 亮部高光"三段式
部位处理手法为什么这样处理
生命条槽体1px 亮描边 + 内槽 inset 上暗下亮的双向阴影 + 顶部 1px 白色斜面；不叠任何等距刻度层把"线框"变成"管子"：上缘亮、下缘暗，眼睛会自动读成有厚度的实体。管子内部一旦再画格子，就同时破坏了"连续量"的语义与管子的体积感
生命填充竖向三段渐变（#FFD9A0 → #FF8C22 → #DB5B08，v5.0 改为暖橙）+ 0 0 16px 暖橙外发光 + 内侧 1px 暖白高光三段比双色更有体积；外发光让条体在暗场景里"亮起来"而不是"贴上去"。橙与下方的金之间隔着深蓝咒力条，两者从不接触（见 03·e 可区分性验证）
前沿光刃2px 纯白竖条 + 双层投影（10px 白 / 22px 青）受击时最需要被看到的量就是"还剩多少"，前沿必须是最亮的一点
虚血残影暖橙深档竖向渐变（#8A3A08 → #3E1404）+ 上缘 1px 暖白高光；0.6s 延迟 / 0.35s 回落加一道上缘高光后残影不再是一块死黑，读数时能分清"残影"与"空槽"。v5.0 起残影改用与生命条同一色相的深档（原来是暗红），受击时读作"这条血量掉了一截"，而不是另一条独立的红条
咒力条同语言、厚度 11px（生命 0.73 倍）+ 8% 处危险色闸门刻度（上下出头 6px + 两端三角）两层条必须"同族不同级"：材质一致保证同一套读数节奏，厚度与色相区分层级。格子去掉后，8% 门槛成为咒力条上唯一的内部记号，它承载的是"能不能开炮"的决策信息，必须比装饰性强
头像框外 1px 亮线 → 2px 深色带 → 内层 1px；内缘 3px 身份色能量线（带 10px 光晕）+ 112° 斜向高光 + 底部 46% 暗角 + P1/P2 角标外亮内深的双描边是金属/能量框的通用做法；斜向高光避免方形头像显得平；底部暗角保证角标可读
顶部压暗带顶部 230px 竖向渐变 rgba(3,6,12,.72) → 透明条组直接压在擂台亮部会失去对比；一条压暗带让两侧条组"浮"出来，比给每个面板加底更干净
菱形豆 v6.0管体五段（#5E4207 → #A8760F → #FFE0A0(40%) → #C08A14 → #6E4E08）+ 左上角 3.5px 三角宝石高光 + 9px 金色外发光；空豆同形制、去发光、内面压到 #1A2130 → #0D121C行动资源是可数的 5 个点。v5.0 曾用"连续条 + 上缘刻度"，但连续条无法表达"一次扣 2 点"——掉 2/5 与回气到 3/5 完全同形。离散豆用"有没有光"区分满 / 空，扣点时两颗同时暗下去，读成一个事件

技能区规范（单排招位）

三格同排、圆心距一律 120px；Q / E 普通技 Ø70 + R 大招主位 Ø96
项规格理由
形状全部圆形，取消方角格圆形天然承载扇形冷却、外圈能量弧与外发光，不需要再挂一个进度条
体量层级大招 Ø96 : 普通技 Ø70 = 1.37 : 11.37 倍足以读出「主位」，同时保证 Ø96 与相邻 Ø70 在 120px 圆心距下仍有 37px 净间隙（见下）
排列方式单排，无弧线：Q(1580,1004) → E(1700,1004) → R(1820,1004)，圆心距恒为 120px，三点同一 y参考图里 T↔E 圆心距 267、E↔Q 只有 160 —— 说明 E/Q 才是同一组技能，T 是被隔开的物品键。同排等距让"同一组"这件事由几何本身说明；斜弧排会引入一个参考图里并不存在的排布
纵向定位圆心 y=1004；键位标签中心落到 y≈1039，与参考图量得的标签带 1027–1051（中心 1039）重合；标签底边距屏底 32px纵向锚点取自参考图实测的标签带，而不是按钮圆心——键位字母是玩家真正盯着找的东西，它该落在实测位置上
净距Q↔E 净距 50px（120 − 35 − 35）；E↔R 净距 37px（120 − 35 − 48）；R 右缘距屏右 52px净距全部为正且 ≥37px，三格在 1/3 缩略图下也不会黏成一团
招位数量每形态 2 个普通技 + 1 个大招：近战 Q 腿击 / E 切形态；远程 Q 超级炮 / E 切形态技能区信息过载，删掉文字后只保留会真正改变战局的招位；其余招式进招式表
轻 / 重共键招位只留键位字母；轻重共键关系移出 HUD，写在招式表与训练提示里按钮上一旦承载说明文字，就会与图标本体的识别责任打架；参考图的招位也不写这些
按钮文字只有键位字母 Q / E / R（11px），无技能名、无派生说明、无秒数形制取自两张实机参考图：原神与鸣潮的右下招位都只标键位字母，技能靠图标本身体现
冷却表现自顶部（-90°）顺时针扫过的暗色扇形（conic-gradient），不写秒数鸣潮 T 键那格的做法；圆形按钮的天然表达，替代底部进度条
形态再切间隔按 E 后在新形态的 E 格上画一圈 0.5s 收束细弧（Ø70 格：周长 195 → 0），无文字同一状态不在形态圆盘与招位格上重复出现；指示器放在触发它的按钮上
能量表现大招能量环与按钮同心贴合：viewBox 96 = 按钮 96px，r=45.5 → 环外缘半径 47，落在按钮 48px 半径内 1px；能量 < 0.5% 时 fgc 不透明度归零环必须落在按钮外缘之内，否则能量为 0 时只剩一圈悬在按钮外的淡蓝，被读成孤立圆圈。另：零长度 dash 在 round 线帽下会渲染出一个圆点，低能量必须连同不透明度一起归零，跨阈值时 dasharray 与 opacity 同步 0.25s 淡入
