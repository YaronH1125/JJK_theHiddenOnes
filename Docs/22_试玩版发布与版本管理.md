## 当前发行状态

已有 Windows 本地试玩候选 `v0.1.0-alpha.1`，来源为 `MenuUI_20261002_222940`。截至本文更新，GitHub 尚未发布 Release；本地 ZIP 也不等于已经公开发行。

玩家随后报告“启动后卡在地面”。该现象尚未定位闭环，暂停背景读取也存在 DirectX 12 非致命 ensure 记录。现有自动检查只确认解压后主菜单可启动，不能替代开始游戏、移动、对战与重开的验收。公开下载前应先处理这些启动 / 运行问题。

## 版本号与构建号

本项目借鉴 [SemVer](https://semver.org/lang/zh-CN/)，用于区分游戏试玩候选；这不是游戏行业统一编号标准，也不把玩法迭代定义为公共 API 兼容承诺。

| 标识 | 本项目约定 |
| --- | --- |
| `v0.1.0-alpha.1` | 第一轮试玩的第一个候选；当前仅本地归档 |
| `v0.1.0-alpha.2` | 同一轮修复或调整后的下一候选 |
| `v0.2.0-alpha.1` | 增加成组功能后开始下一轮试玩 |
| `v0.1.0-beta.1` | 同一轮功能基本固定后，按实际验收进入兼容性与稳定性测试 |
| `v0.1.0` | 去掉预发行后缀的阶段版本；仅在该版本约定的交付范围通过后使用 |
| `v1.0.0` | 未来达到项目定义的正式交付目标时使用 |

发行号说明“这是哪一版”，构建标签说明“由哪个包整理”。例如当前候选构建标签为 `MenuUI_20261002_222940`，包内构建号为 `20261002.222940`。日期不替代版本递增；修复后不能仍发相同发行号和相同文件名。

源码提交、Git tag、二进制与资产快照应建立对应。不能把打包时的当前 HEAD 直接写成旧 exe 的构建提交。当前候选尚未建立正式 tag 与源构建提交的完整对应；最终公开候选应从已确认提交重建并记录资产快照。

## 给试玩者的交付内容

每个候选至少包含以下内容：

- Windows 程序和全部必要资源目录、运行库安装包。
- 简短说明：启动入口、按键、训练 / 对战、暂停 / 重开 / 退出和已知问题。
- `VERSION.txt`、`release.json`、逐文件 SHA-256 清单与 ZIP 的 SHA-256。
- GitHub 发行说明中的功能范围、验证机器范围及未关闭问题。

当前候选命名：`JJK_TheHiddenOnes_Playtest_v0.1.0-alpha.1_Win64_20261002.zip`。包内根文件夹为 `JJK_Playtest_v0.1.0-alpha.1`，避免给运行依赖再增加过长前缀。

玩家应完整解压到 `D:\Games`、`C:\Games` 等较短目录，保留 `Engine/` 和 `JJK_theHiddenOnes/`。当前 UI 的运行库在深路径下实测返回 Windows 错误 206；短路径建议来自该候选的实际兼容性限制，不表示必须使用 D 盘。

当前 exe 可直接打开主菜单。`Play.cmd` 额外开启顿帧并设置 60 FPS 上限；60 是上限，不是性能达标证明。正式入口的下一步目标是通过验证后将认可的默认设置放入游戏，使玩家仅双击 exe 即可获得同样的体验。

## GitHub Release 附件

GitHub Release 应关联最终源码 tag，预览版本勾选 **This is a pre-release**；可先保存 Draft，附件与说明齐备后再发布。[GitHub 发行管理](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)

当前 ZIP 为 **3,243,444,666 字节，约 3.24 GB / 3.02 GiB**。GitHub 单个 Release 附件必须小于 2 GiB，不能将这个完整 ZIP 直接上传为一个附件。[GitHub 附件限制](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

可选分发方式：

| 方式 | 交付要求 |
| --- | --- |
| GitHub 分卷 | 每卷小于 2 GiB，建议 1.5 GiB；提供全部分卷、各卷校验值和重组说明；重组后验证完整 ZIP 的 SHA-256 |
| 外部完整 ZIP | 使用已确认可访问的下载地址；Release 描述链接、大小、SHA-256 与版本；不写尚不存在的网盘链接 |

分卷比普通 ZIP 多一步操作。制作分卷时要验证重组、完整解压及程序启动，不能只上传第一卷。为当前阻塞候选不自动制作 / 上传附件；修复后以新候选号生成对应附件。

GitHub 自动生成的 **Source code (zip / tar.gz)** 是 tag 对应源码，不是游戏运行包；本仓库还排除了第三方原素材，不能让试玩者下载它来运行游戏。

## 发布前检查

1. 关闭“启动后卡在地面”等影响主流程的问题，并验证暂停背景读取。
2. 固定源码提交、项目资产和发行号，完整构建菜单与战斗的同一候选。
3. 从交付 ZIP 重新解压，使用首次运行设置，执行“主菜单 → 开始 AI → 移动与出招 → 两种炮 → 领域 → 胜负 → 重开 → 暂停 / 设置 → 退出重启”。
4. 单独验证蓄力时暂停、失焦、取消与旧松键，不出现幽灵发射、残留声音或输入锁死。
5. 完成正常资源整局，记录目标硬件、分辨率、画质及帧时间；另一台机器未验证时明确写出。
6. 校验 ZIP / 分卷，核对说明、截图 / 视频与实际候选一致，再关联源码 tag 并整理 Draft。
7. 发布后保存旧候选、校验值与更新记录；有内容变化时换新版本，不能覆盖旧包掩盖失败。
