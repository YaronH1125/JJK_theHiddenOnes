版本：v0.2；更新日期：2026-09-16；实施与自测状态：已完成白盒规则闭环与自动验收，详见第 7 节。

## 1. 目标与进入条件

基于 M2 的可靠单次攻击，完成三段连击、缓存、持续防御、方向闪避、主动取消、条件投技与完整受击生命周期。M2 的重复命中、异常清理与重置问题必须先解决。

本阶段以占位动作也能验证完整攻防。无振刀、精确防御、拆投、空投、墙弹和联网逻辑；不新增独立防御条。

## 3. 开发步骤与局部检查

### M3.1 将单段扩为三段

一个 MeleeCombo GA 持有当前段数，每段独立命中记录和窗口。衔接时更新段号及动画段落，不重新误授予能力。第三段产生配置的击退，结束后回到可行动。

局部检查：单击只走第一段；按窗口输入可连续三段；每段伤害次数与配置一致。

### M3.2 增加单槽缓存

请求保存动作、方向和时间，窗口打开时重新检查状态、目标与资源，成功消费后立即清除。过期、死亡、模式切换和重置时丢弃；缓存不能授予本来不允许的取消权限。

持续防御单独记录按下/松开，受击期间松开也必须收到；菜单切换或失去游戏输入时释放持续意图，避免恢复后粘住。

局部检查：过早输入过期后不补招，有效缓存只执行一次。

### M3.3 接持续防御与方向闪避

共享结算按攻击来向、角色防御朝向和类型判断，不按相机朝向决定正面。防御只产生配置的防御结果与硬直，无时机奖励。防御/无敌结果按本段规则消费命中，不能下一采样绕过第一次防住的结果。

闪避单独管理位移、无敌和恢复窗口，结束/中断释放自身状态。霸体与无敌分开：霸体仍可扣血，只抵抗规定等级打断。

局部检查：正面防住、侧后方按规则命中；闪避只在规定窗口免伤；结束后可恢复正常受击。

### M3.4 接 Shift 闪避取消与行动资源

只有当前动作允许、处于窗口且资源足够时提交 Shift 闪避取消；Dodge 先通过全部检查，才停止旧 GA 检测、清理会话并进入闪避。失败保留原动作。普通闪避起测成本 1，取消闪避总计 2，不叠加扣成 3；恢复或合法衔接后才能执行 E/新招。没有独立原地取消键。

F 为按住防御，不能直接取消攻击；右键不再防御。Shift 无方向默认后撤，按住不连续闪避，闪避恢复不可自取消。远程右肩瞄准镜头在 M6 实现。

配置合法变招集合，不允许所有动作任意互相取消。普通受击、投技演出和死亡不能用普通取消脱离；已经造成的伤害保留。

局部检查：窗口外、资源不足均拒绝，合法取消后可继续行动且没有旧招延迟命中。

### M3.5 做单个条件投技

普攻结算遇到防御目标时，检查距离、方向、地面、可抓取状态与配对占用。条件满足才转为投技结果，同一次接触不再追加普通命中伤害。

先验证配对位置能在边界内安全落地，再限制双方控制和播放配对动作；不合法时退回原防御结算。任何一方死亡、销毁、重置或动画失败都释放双方配对、限制和引用。

局部检查：合法条件可投，距离过远/空中/已有配对不可投；边缘不会把目标移出擂台。

### M3.6 串联受击、击退、倒地、起身和死亡

将状态与动作中断规则明确交给 GA/GE 管理，AnimInstance 只读。倒地保护期间按配置拒绝再次进入普通连段；起身结束才恢复行动。死亡停止所有主动请求与现有攻击，等待重置。

普通移动、Root Motion、击退和投技配对同一时刻只有明确的控制来源；退出恢复正确的移动模式和旋转设置。

局部检查：受击→倒地→起身后可以移动攻击；死亡后不能闪避/取消逃离状态；重置双方都可继续。

## 5. 必须演示的闭环

三段普攻 → 对手防御 → 合法条件转投 → 双方释放 → 对手攻击 → 玩家闪避/防御 → 合法取消变招 → 击退倒地起身 → 一方死亡 → 重置再次出招。无 AI 时分段用调试入口触发，并标明操作方式。

### 7.2 本轮修改与状态持有者

- 修复重复声明、缺失成员/方法、数组类型不一致、未定义 ASC 变量与日志链接错误，使原初稿可正式构建。
- `MeleeComboAbility` 持有当前段、衔接窗口、Montage Task、霸体和攻击标签；命中窗口与衔接窗口分开，段间清旧 Task/计时器，结束主动停止自身 Montage。第三段结束不再循环回 A1。
- `CombatInputComponent` 持有轻重会话、单槽缓存、按下时采样的方向/缓存时锁定目标及防御意图。缓存后到覆盖，消费、过期、目标死亡/销毁、中断、菜单停止请求、失焦、切形态、死亡和重置不补招。未锁定允许空挥；零成本拳脚不因行动资源不足被拒。
- `ArenaPlayerController::PostProcessInput` 统一处理同帧优先级：待处理战斗中断→合法 Shift→松键→新动作；F 意图先记录。Shift 成功清旧会话，失败保留合法松键。菜单/模式接入使用 `SetCombatInputEnabled`，同时阻止共享入口与释放持续输入。
- `DodgeAbility` 持有单一 RootMotionSource 位移、无敌/恢复标签及计时器；`StanceSwitchAbility` 持有切换状态与完成事件。闪避恢复期禁止攻击、再次闪避和 E。
- `CombatStateGameplayEffect` 的每次 Spec 赋予受击、防御硬直、倒地、起身、死亡、防御或投技标签；角色保留效果句柄并协调双方与移动恢复。数值变化分别经过 Damage、ModifyActionResource、RestoreCursedEnergy GE。
- 投技先验证距离、朝向、双方地面状态、占用、胶囊间距、边界、落点及路径阻挡；通过后才锁双方。配对持续监察双方 Montage，死亡/销毁/重置/停动画对称释放，失败保留防御结算，不双重伤害。
- 普通移动和跳跃受共享动作限制；闪避、攻击、受击、击退与投技不争抢移动/旋转控制。目标消失仍可释放另一方；玩家销毁后重生重新交由原控制器接管。
- 新增 CursedEnergy/MaxCursedEnergy；保留 Energy 作为领域能量字段。M3 近战零咒力成本，普通命中每段攻击实例回 3，投技整个配对回 3，防御/免疫/空挥无收益。远程炮、咒力被动恢复与领域逻辑留 M6。

### 7.6 复测与操作

编辑器仅开启本项目一个实例，C++ 正式构建前保存并关闭编辑器。命令在项目根目录运行：

```powershell
python Scripts/ue_python.py Scripts/M3_create_assets.py  # 停止 PIE 后幂等修复资产
python Scripts/run_m3_acceptance.py                    # 118 项规则/回归；可用 -nullrhi 编辑器跑时序
python Scripts/run_m3_demo.py                          # 有图形编辑器；20 项与三张截图
```

实机：左键点按/长按拳击，Q 点按/长按腿击，Shift 闪避兼取消，F 按住防御，E 切形态；Tab/镜头沿用 M1。调试控制台 `JJKOpponentGuard true/false` 切对手防御，`JJKOpponentAction 0/1/2/3/4` 分别请求轻拳/重拳/腿击/重踢/闪避，`JJKDebugHud` 显示阶段、段号、缓存、行动资源、咒力与真实标签，`JJKResetFighters` 重置。

### 7.7 M4 交接

**允许进入 M4：是。** 本轮未发现永久硬直、无限取消、投技单方锁定或死亡后能行动的阻塞。

- `CombatInputComponent` 是玩家/对手的共享请求入口；使用返回的 Executed/Cached/拒绝原因，不能旁路直接播放攻击来代表动作成功。
- `FighterCharacter::CanAct`、ASC 标签与 `OnRecovered` 提供真实恢复边界；`OnComboEnded` 在攻击能力结束后广播（包括被中断），不要用动画长度猜训练连击结束。
- 菜单调用 `ArenaPlayerController::SetCombatInputEnabled(false/true)`，对手模式停止调用 `CombatInputComponent::SetRequestsEnabled`，释放持续意图、会话与缓存；恢复后要求新按下。
- `TrainingGameMode::ResetTraining` 为双方集中重置入口；个体 `ResetToInitialState` 也能从投技/死亡状态退出，不重复授予能力。
- M4 资源设置覆盖 ActionResource、CursedEnergy、Energy 时仍经共享规则与 GE；无限资源不能仅改 UI。对手固定防御可直接复用防御按住/松开入口。
