# M2：单次攻击闭环

版本：v0.1；建立日期：2026-09-15；实施与自测状态：待核验。

[开发过程导航](README.md) · 上一阶段：[M1](M1_基础训练擂台.md) · 下一阶段：[M3](M3_连招与核心攻防.md)

## 1. 目标与进入条件

用一次普攻打通输入、GA、动画、检测、GE、受击、恢复和重置。M1 的双方角色、独立 ASC、目标与白盒必须可运行；准备一段可用攻击 Montage 和受击占位动作。

本阶段只实现一个攻击段，不提前做三段连招、完整防御、正式 UI 或炮击。必须提前做最小死亡禁止动作与异常清理，不能把延迟伤害问题全部推迟到 M3。

## 2. 交付与职责

| 交付项 | 职责 |
| --- | --- |
| 共享动作请求入口 | 玩家和开发调试对手都提交攻击意图，返回执行或拒绝原因 |
| MeleeCombo 的单段原型 | GA 管激活、Montage、窗口、结束与取消 |
| AttackDefinition 单段配置 | 动画、命中段、伤害、轨迹参数与攻击类型 |
| CombatHitComponent | 活动窗口采样、攻击实例记录、命中去重与结算入口 |
| 伤害 GE 与 HitReact | 正常伤害修改属性，产生受击/中断与恢复 |
| 调试重置入口 | 集中取消战斗、恢复属性与位置，供后续面板复用 |

动画通知只报告事件，不直接扣血或持有跨角色状态。Cue/粒子只做表现。具体对象分工见 [架构设计](../02_架构设计.md)。

## 3. 开发步骤与局部检查

### M2.1 先验证请求到能力

将攻击 Input Action 映射到项目请求，检查角色存活、ASC 初始化和当前动作限制，再尝试激活已授予能力。能力不能在每次按键或重置时重新授予。

先让 GA 只打印开始、结束和拒绝原因，确认玩家与调试对手走相同入口。重复按键不产生同一角色的重复活动实例。

局部检查：一次合法输入对应一次激活；死亡/未初始化时拒绝，失败有原因。

### M2.2 接动画和窗口生命周期

GA 播放 Montage，管理起手、有效、恢复三个阶段。通过通知打开/关闭检测，事件带当前动作实例身份，拒绝旧动画遗留事件。

所有退出路径主动关窗口、停止相关任务并清理临时状态；不能等最后一个通知来恢复角色。通知丢失或 Montage 播放失败也要结束能力。

局部检查：正常结束和强制停止 Montage 后均能再次攻击，检测不残留。

### M2.3 做轨迹检测与跨采样去重

在有效窗口按拳部 Socket 前后位置 Sweep，过滤自身和非法目标。去重键为攻击实例、命中段与目标，集合保持到该段结束；新攻击可再次命中。

快速位移/旋转按轨迹跨度补采样，先在调试显示中确认轨迹，再连接伤害。不把“每帧有一次命中”当作合理的多段伤害。

局部检查：同一目标多碰撞部件、同一窗口多次采样都只产生一条有效命中。

### M2.4 接统一结果与受击

结算先检查有效性、去重和无敌等已具备规则，再生成伤害结果，经 GE 修改生命、通知受击和统计。未实现的防御/投技留清晰扩展点，不写伪成功结果。

HitReact 明确打断哪些活动能力，恢复后允许行动；最小死亡处理取消活动攻击、禁止新动作并等待调试重置。受击和死亡均不能只改动画而不改规则状态。

局部检查：一次命中只扣一次血、产生一次受击；受击结束后可再次请求动作。

### M2.5 明确同批次命中顺序

为测试场景定义“同批次”为本次命中收集后统一处理的一批接触结果。默认先筛出有效普通攻击接触，再按稳定次序结算，允许这一批已有效接触换血；被打断后未来窗口产生的接触不再有效。

记录批次标识与双方结果。若现有实现直接即时结算导致遍历顺序决定胜负，应修正本批处理方式，不把它称为已支持换血。致死同批次结果也需记录，不要求实现联网确定性。

局部检查：固定双方位置与出手时刻重复触发，结果符合记录规则。

### M2.6 接入最小调试与重置

显示动作请求结果、当前 GA/阶段、关键标签、攻击实例/命中段、命中次数、双方生命。重置顺序沿用架构文档：停请求 → 取消能力 → 清临时对象/事件 → 复位双方 → 恢复属性和统计 → 恢复目标与模式。

开发调试入口可触发对手攻击、强制中断和重置；动作仍经过共享请求，直接伤害仅用于明确标记的异常注入。M4 再接正式训练面板。

局部检查：在起手、有效、恢复各阶段重置，等待超过原动作时长后没有补发命中。

## 4. 本阶段自测

| ID | 前置与操作 | 预期结果/观察点 |
| --- | --- | --- |
| M2-T01 | 有效距离攻击一次，再在范围外攻击 | 前者一次 GE/受击；后者空挥，无远程扣血 |
| M2-T02 | 同目标多碰撞部件、有效窗口连续查询 | 同一实例同一段仅一次伤害；记录去重键 |
| M2-T03 | 前一次攻击结束，再攻击同目标 | 新实例可再次命中，旧去重记录不阻止新攻击 |
| M2-T04 | 快速连续按攻击；在禁止状态提交请求 | 无重复激活，拒绝原因可见 |
| M2-T05 | 起手/有效/恢复时分别停止 Montage 或注入受击 | 窗口与状态清理；恢复后可再次出招 |
| M2-T06 | 在上述阶段分别死亡/重置，等待超过原动作时长 | 无延迟伤害、重复授予或残留状态；死亡时不能出招 |
| M2-T07 | 攻击过程中销毁目标或结束 PIE | 无失效引用访问、残留回调错误 |
| M2-T08 | 双方调试同步攻击，至少重复 5 次 | 同批次有效普通接触按记录换血；中断后未来接触失效 |
| M2-T09 | 30/60/120 FPS 下复现一次快速攻击 | 无明显漏判或重复扣血，记录实际帧率与轨迹差异 |
| M2-T10 | 仅关闭命中粒子/声音后重复 T01 | 伤害和受击规则保持，表现不控制结算 |

当前均未执行。M2-T05/T06 可用开发入口触发，不要求此时已有完整攻防菜单。

## 5. 必须演示的闭环

进入擂台 → 攻击命中一次 → 查看生命与受击 → 对手恢复 → 再攻击 → 动作中重置 → 等待旧动作时长后确认无伤害 → 再次攻击正常。另演示一次同批次换血。

重复伤害、残留窗口、重置后补发攻击或永久无法行动均阻塞 M3。动画精细度和正式 HUD 不阻塞。

## 7. 排查与记录

重复伤害先看去重集合生命周期与多碰撞命中；命中无受击先查 GE/事件链路；动画结束仍不能动先查 GA 结束和标签来源；偶发旧命中先查实例校验与延迟回调。
