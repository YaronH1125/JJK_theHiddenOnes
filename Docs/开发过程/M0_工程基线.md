## 1. 目标与范围

形成一个可重复构建、打开和运行的 UE 5.8.2 C++ 工程，为后续战斗开发提供可恢复基线。本阶段完成工具链、项目配置、版本管理与模板运行，不建设战斗系统。

当前已存在 `JJK_theHiddenOnes.uproject`、Editor/Game Target、Source 和 Content。编写本文件时仅静态确认这些文件存在；uproject 的引擎关联为 5.8，插件列表显式列有 StateTree、GameplayStateTree 和建模工具，未显式列出 GameplayAbilities。此信息不是插件运行状态或编译成功的证明，实施时重新检查。

## 3. 开发步骤与局部检查

### M0.1 核对工程身份和入口

读取 uproject、两个 Target、模块 Build.cs、默认地图和默认 GameMode。确认模块名 `JJK_theHiddenOnes` 与目标配置一致，记录当前实际启动地图和角色。

已有工程满足起点就沿用；仅在工程确实缺失时创建 Third Person C++、None 变体。不要因为发现其他模板变体就推断创建错误。

局部检查：能说明“打开哪个工程、使用哪个引擎、启动哪张地图、生成哪个角色”，并给出对应配置位置。

### M0.2 建立版本管理与忽略规则

检查当前目录是否已受版本控制；缺失时建立本地仓库。跟踪 Source、Config、Content、uproject、Docs 与必要项目脚本，忽略 Binaries、Intermediate、DerivedDataCache、Saved 和 IDE 本地缓存。不要用忽略规则掩盖未归档的模型源文件。

对大体积资产记录采用的存储方式；本地 Git 不等同于异地备份。将当前文档和工程基线形成可识别版本，确认无缓存误入待提交清单。

局部检查：可以从版本或快照定位此次基线；资源清单中没有“只在缓存目录里”的正式依赖。

### M0.3 接入最小 GAS 构建依赖

核对 GameplayAbilities 插件启用情况，在项目模块中按实际使用加入 GameplayAbilities、GameplayTags、GameplayTasks 等依赖；Enhanced Input 等模板依赖保留。先让依赖可构建，不在本阶段一次性生成全部能力类。

StateTree 等现存模板依赖先追踪引用，确认无使用后再考虑移除；目标 AI 仍按 M5 的 Behavior Tree 方案推进。

局部检查：重新生成工程文件后构建成功，没有缺模块、缺头文件或插件加载失败。

### M0.4 做可重复的 Editor 构建

关闭编辑器后构建 `JJK_theHiddenOnesEditor` 的 Development Editor / Win64 目标；保留实际命令或 IDE 配置与构建日志。不要把一次 Live Coding 成功作为完整编译证明。

首次失败先定位第一条实际错误，区分工具链、模块依赖、生成代码和资产问题；修复后重复该构建，不盲目递归删除工程目录。

局部检查：构建日志结束状态成功，重新启动编辑器能加载项目模块。

### M0.5 跑通模板并确认配置持久化

打开默认地图进入 PIE，测试移动、镜头、退出与重进；保存必要配置，关闭编辑器再打开重复一次。清点模板变体和当前引用，暂未使用但依赖不明的内容只登记。

局部检查：没有错误 GameMode、重复角色、输入失效、模块丢失；关闭编辑器后结果仍成立。
