### 5.2 缺陷 V-M2-01：IA_Attack 资产丢失，物理输入链在提交树上失效

**现象**：`BP_ArenaPlayerController.AttackAction` 与 `IMC_Training` 左键映射引用 `/Game/Training/IA_Attack`，该资产既不在磁盘也不在任何 Git 历史中。C++ 侧 `if (AttackAction != nullptr)` 静默跳过绑定——冷启动编辑器后按左键无任何反应。

**事故链（依编辑器日志还原）**：

1. 09-15 21:57（UTC，下同）编辑器启动即报依赖缺失："Skipped package /Game/Training/IA_Attack … does not exist either on disk"。
2. 22:04 [M2_fix_inputs.py](../../../Scripts/M2_fix_inputs.py) 重建资产：`duplicate_asset` 失败走 `create_asset` 回退，资产**仅存在于内存**；脚本虽有 `save_asset` 调用，但正式保存未落盘（随后 22:04:24 二次运行报 "CanCreateAsset … running unattended"）。
3. 22:17 编辑器自动保存将该资产写入 **`Saved/Autosaves/`**（gitignored 临时目录）——证明此刻包仍为 dirty 未保存状态。
4. 编辑器关闭后内存资产丢失；`Content/Training/IA_Attack.uasset` 从未产生、从未提交。

**影响与证据**：

- 验证当日编辑器内实读：`attack_action = None`（即使在当时仍存活的编辑器会话中，磁盘重载后的 BP 引用已断）。
- 冷启动必现：日志中多个新启动会话重复出现同一依赖解析失败。
- 后果：完成标准"输入到 GE/受击的完整链路有日志或录像证据"仅对**程序化路径**成立；M2 修复记录第 3 条"真实分发验证通过"在全部脚本中找不到按键注入代码（无 InjectInput/PressKey），48 项断言的攻击均经 `notify_attack_pressed()` 触发，该声称无归档证据支撑。

**附带发现**：M2 活体复验时连接到的编辑器会话（当日 05:56 启动、持续运行）内存中仍保有 09-15 晚创建的 IA_Attack（对象指针与事故链日志一致），故复验在该会话内输入映射尚可解析；**该会话一旦关闭，输入映射随之丢失**。
