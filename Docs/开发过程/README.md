# 开发过程文档

版本：v0.1；建立日期：2026-09-15。本文档组细化 [开发计划与验收](../05_开发计划与验收.md) 的 M0—M7，不改变首版范围。

项目 IP 为《咒术回战》，首个实机角色为石流龙；UE 5.8.2、GAS、单机 1v1 训练擂台、自由镜头。M0 已有工程基线验收；2026-09-15 M1 完成修复并通过 31 项自动检查及 3 次重新进入。M2 已完成单次攻击闭环；2026-09-16 M3 完成白盒攻防、118 项规则回归与 20 项图形闭环/边界验收。M4—M7 仍为实施指导，未验收内容中的类名与资产名为建议名称。具体结果和限制以各阶段记录为准。

## 2. 如何执行

角色战斗以 [08](../08_石流龙战斗系统设计.md) 最新正文为准：双形态、拳腿轻重击、两类手动蓄力炮、领域自动满威力曲线追踪球。SLL-T01—T24 为后续原型验证，不追溯改变既有 M0/M1 验收。M2 增加轻重输入识别小原型，M3 完成近战攻防与 Shift/F/E，M4 训练资源与清理，M5 共享 AI 请求，M6 集成瞄准、远程炮击及领域，M7 包内回归。原作消耗/熔断研究中的建议尚未自动转为已定游戏参数。

M2 agent 从 [M2 第 0 节](M2_单次攻击闭环.md) 的阅读清单开始；不用逐篇实现全部后续阶段。08 决定角色行为，阶段文档决定当前交付子集，验收记录决定哪些功能实际通过。

1. 先核对已有实现与前一阶段验收记录，再做本阶段缺失项。已有工程不重复创建，已有功能不根据文档直接重写。
2. 按详细文档中的小步骤推进，每个步骤先通过局部检查，再增加下一部分。
3. 阶段结束执行自测表和完整闭环脚本；填写实际结果、日志/录像位置及失败复现步骤。
4. 影响当前闭环的失败修复后重测；仅外观打磨等不阻塞项可以明确记入后续阶段。
5. 阶段结论同步回总计划。文档完成不等于实现完成，运行通过也不等于独立打包通过。

## 3. 前后阶段的依赖边界

| 容易提前依赖的功能 | 当前阶段如何处理 | 后续接入点 |
| --- | --- | --- |
| M2 尚无完整死亡与训练面板 | 先具备死亡禁止动作、取消攻击和调试重置入口；用调试命令复现异常 | M3 补齐死亡动作，M4 接入面板 |
| M3 尚无行为树 | 用仅开发环境可用的动作请求入口让对手防御/攻击，仍经过共享规则 | M4 固定防御模式，M5 行为树 |
| M4 尚无正式 AI | 提供模式枚举与切换接口，AI 选项禁用并说明未接入；静止和固定防御真实可用 | M5 完成 AI 模式最终验收 |
| M4 尚无炮击与绝技冷却 | 用最小测试能力配置真实 GE 消耗/冷却，验证训练规则；记录测试能力身份 | M6 用正式技能再做集成验收 |
| M5 尚无石流龙正式技能 | AI 先使用 M3 已有普攻、防御、闪避和条件投技 | M6 补技能槽与距离策略 |
| M1 缺正式角色资产 | 验证骨骼可用性并登记缺口，使用明确的占位模型继续 | M6 正式模型和动作完整接入 |

上述临时入口不绕过战斗结算，不作为正式交付内容。暂未到阶段的检查写“待后续集成”，不得填成通过。

## 4. 自测与证据约定

每项用例使用 `M阶段-T编号` 标识。各阶段默认状态为“未执行”；“通过”必须有实际结果。“阻塞”写明依赖和恢复条件；确实不适用时写理由，不跳过当前范围内功能。

记录工程版本或文件快照标识、UE/构建配置、运行地图、设备、分辨率、是否 PIE/独立运行包、测试参数。故障至少包含前置状态、操作顺序、预期、实际和复现频率。

自动化优先覆盖输入消费、命中去重、资源规则和重置幂等等有明确断言的逻辑；动画、镜头、资产与打包用实际运行验证。不要求给纯配置或每个蓝图节点编写测试。30/60/120 FPS 是指定阶段的跨帧率检查档位；设备达不到时记录实际帧率，不能以设置值代替测量值。
