# M5：AI 对战

版本：v0.3；建立日期：2026-09-15；验收日期：2026-09-16。M5 白盒 AI 对战已完成，可进入 M6。

[开发过程导航](README.md) · 上一阶段：[M4](M4_训练系统.md) · 下一阶段：[M6](M6_角色与技能表现.md)

## 1. 目标与进入条件

让一个对手根据距离、资源和可观察状态进行攻防，经同一能力规则完成胜负与重开。M4 的模式切换、训练设置和重置已稳定；M3 的普攻、防御、闪避、条件投技可用。

采用 Behavior Tree + Blackboard。M5 先使用已有拳腿轻重击及公共动作；M6 再加入形态切换、炮击、领域与领域中反制决策，详见 [08](../08_石流龙战斗系统设计.md)。本阶段不依赖正式远程技能、不建设感知系统或多人战术，也不长期保留另一套并行 AI 框架。

## 2. 预期交付与数据

| 对象/配置 | 需要承担的内容 |
| --- | --- |
| ArenaAIController | 接受 GameMode 指定目标，启动/停止决策与移动 |
| Blackboard | 目标、距离、可行动性、当前决策所需的观察值 |
| Behavior Tree | 接近、侧移、后退、攻击、防御、闪避与等待分支 |
| 动作 Task | 发共享请求，区分立即失败、已缓存、执行中、结束与中止 |

生命/资源/冷却的真值仍在 ASC；Blackboard 可保存决策快照，但不能维护另一套可扣减数值。调试显示当前分支、意图、请求结果和等待原因。

## 3. 开发步骤与局部检查

### M5.1 接入目标、模式和寻路

GameMode 分配对手目标，进入 AI 模式才运行行为树，离开则停止行为与移动。白盒内核验 NavMesh 覆盖，记录导航代理尺寸与角色 Capsule 是否匹配；边界外不可到达。

失效目标进入等待/重新验证，禁止对空引用持续移动。木桩和固定防御沿用 M4 实现。

局部检查：模式切换可反复进行；进入 AI 后能识别正确目标并接近，退出立即停止主动意图。

### M5.2 先做距离行为

按距离选择接近、侧移或后退，目标点必须可行走且在边界内。采用不同进入/退出阈值或最小保持时间，避免距离阈值附近每帧切状态。

侧移方向可定时更换，后退在无空间时改为等待/侧移，不向墙内无限寻路。移动失败有明确返回与重试间隔。

局部检查：目标移动时 AI 可重新接近；在墙边不会持续抖动或越界。

### M5.3 接共享动作 Task

Task 提交动作请求，不能直接扣血或只播放攻击 Montage。区分“已缓存”和“已激活”：缓存请求需要过期/消费结果，不能立刻当攻击完成，也不能无限等待。

订阅与本次动作实例相关的结束事件，处理能力瞬间完成、激活失败、资源不足和冷却。任务结束/中止解除自己的订阅；取消动作须遵守该动作中断规则，不清除其他行为贡献的状态。

局部检查：AI 在受击禁止时请求会失败并等待，恢复后能继续；任务不会永久挂起。

### M5.4 增加攻防选择与反应参数

近距离请求普攻，通过配置概率/观察状态决定防御或闪避。投技沿用普攻接触防御目标后的条件分支，不给 AI 增加无条件远程抓取。

决策仅使用已可观察的攻击阶段、距离和资源等信息；不读取玩家尚未表现的输入来瞬间反制。调节反应延迟与决策间隔，保留固定随机种子或决策日志便于复现。

局部检查：改变难度参数能解释行为变化；不会每帧全知反击或无资源出招。

### M5.5 处理移动与战斗控制权

Root Motion、闪避、击退和投技开始时停止/暂停冲突的 AI Move 请求；动作结束按状态恢复决策。不能由寻路持续覆盖击退位置或将投技双方拉开。

切模式、死亡、重置都解除持续防御和旧动作缓存；已发生的命中不回滚。

局部检查：追击中受击会正确后退/硬直，恢复后重新决策；切木桩后没有旧追击。

### M5.6 完成胜负与重开

AI 对战中一方死亡后停止双方新主动行为，显示结果；结算本批已有效接触后再决定胜负，双方同批次死亡可用“平局”作为默认显示并记录规则。结果事件只发一次。

重开调用 M4 统一重置，清对局结束状态并恢复 AI。接通之前禁用的 AI 选项并更新面板说明。本阶段结束前建议产出一次 Development 独立运行包，尽早暴露地图、行为树与导航依赖问题。

局部检查：玩家赢、玩家输、平局/重开均无残留 Task 或重复结果。

## 7. 已落地结构与参数

- `AFighterAIController` 接受 GameMode 唯一目标；`BuildTree` 创建原生 `BT_Arena` 和 `BB_Arena`，由 UE 的 `UBehaviorTreeComponent` 调度。树和节点随 Runtime 模块打包，无编辑器脚本运行依赖；当前是原生固定树，没有 Content 下可双击编辑的图形 BT 资产。
- 树结构：Sequence → `UBTTask_ArenaDecide`（游戏时间决策节流）→ Selector → 七个 `UBTDecorator_ArenaBranch` + `UBTTask_ArenaAction` 分支：Approach / Strafe / Retreat / Attack / Defend / Dodge / Wait。任务按树实例分配，旧 Tick/Timer 决策实现已移除。Controller Tick 只采集可观察状态及停止冲突寻路。
- Blackboard：Target、Distance、CanAct、TargetAttacking、ActionResource、Branch。生命和资源仍以 ASC 为真值。
- 导航：`RecastNavMesh-Arena`，SupportedAgents 半径 42、高 192 cm；Capsule 半径 42、半高 96 cm；动态生成，固定池 1024 瓦片。场内目标需通过代理投影和完整路径查询，白盒安全半径 1100 cm；墙边后退失败只尝试一次侧移，再等待 0.6 秒重试。
- 参数在 Controller 的 `FArenaAIParams`，可从 Blueprint/Python 的 GetParams/SetParams 或 Details 修改；生效于后续决策周期。默认攻击距离 200、退出 260、过近后退 120 cm；决策周期 0.4、反应延迟 0.25、移动分支最短保持 0.6、防御保持 0.8、侧移换向 1.2 秒；攻击概率 0.65、重拳偏好 0.25、防御概率 0.35、闪避概率 0.25，固定随机种子 1337。
- 调试：`JJKDebugHud` 显示分支、请求/等待原因和订阅数量；`GetDecisionLog` 返回最近 64 条带游戏时间的决策。`DebugRequestBranch` 为非 Shipping 复现入口，指定分支仍经过共享规则，不直接激活 GA/扣血。
- Task 在请求前绑定 ASC 激活/结束事件，按本角色能力实例匹配；缓存使用单调编号区分消费、覆盖与过期。清理只删除自身缓存和委托；硬超时 5 秒释放任务订阅，不强行取消不允许取消的动作。切模式/菜单/重置由 GameMode 统一停止能力和持续输入。
- 胜负：至少跨过首次观察死亡的帧，并等双方接触队列清空后结算；同批双亡显示平局。结果计数每局加一次，自动打开结果面板；菜单中的重置保留暂停，返回战斗后恢复 AI。

## 8. M6 接入说明

正式炮击、瞄准、蓄力、领域及其自动球尚未实现，本页尾部这些增量用例仍待 M6 集成，不计为 M5 已通过。

1. 保留共享请求入口。在 Task 的分派处增加正式技能请求，提交前绑定对应 ASC 能力实例，消费/冷却/中断继续由 GAS 校验；禁止 AI 直接结算伤害。
2. 新增正式射程、可观察施法状态和偏好参数，距离策略接入 `Decide`/分支门槛；不得读取玩家未表现的按键或缓存意图。
3. 领域外蓄力炮需要专用任务阶段：请求蓄力 → 有限等待 → 主动松开发射，或走共享 Shift 合法取消；资源不足必须退出持炮。依据实际技能时长调整任务期限，不能照搬当前近战 5 秒硬上限作为蓄力规则。
4. 领域自动炮由领域能力驱动；AI 只根据已有来弹/领域表现选择防御、掩体或压制。受击不删除在途球，也不打断不存在的自动蓄力。
5. M6 必须重跑本阶段模式/菜单/死亡/目标销毁/重置闭环，并增加正式技能资源不足、蓄力取消、领域暂停/结束和在途命中用例；开发 Probe 的成功不能代替正式技能验收。
