## 3. A 类：进入完整 M7 交付流程前补齐

### A01 右键按住瞄准接通

- [ ] 接通远程右键按下/松开 → 瞄准意图 → 有效瞄准状态 → 镜头与朝向；补齐右肩偏移和恢复。
- [ ] 验证近战不瞄准，松右键不发炮，Shift/F/切形态/菜单/失焦/死亡/重置不粘住镜头或输入。

依据：`FighterCharacter.cpp::SetAimIntent` 只写 `bAimIntent`；`TickAimCamera` 读另一变量 `bAiming`，本次源码搜索未见两者接通或 `bAiming` 赋值，未见右键绑定调用。当前镜头逻辑仅插值臂长，未见设计要求的右肩偏移。需同时核验蓝图实际绑定，不能只凭存在函数认定可用。验收：M6-T18，真实鼠标操作录像。

### A02 炮击方向、遮挡和共享攻防

- [ ] 镜头到瞄准点、炮口到最近阻挡全路径检测；中间墙体截断，炮口嵌墙拒绝，特效终点与命中一致。
- [ ] 锁定身份与瞄准方向解耦；释放时固定发射方向，锁向前摇不继续瞬时追随目标。
- [ ] 两种手动炮与领域球接入明确的防御、闪避免疫/保护、受击和训练统计口径。

依据：`ChargedBlastAbility.cpp::FireOnce` 当前锁定目标直接覆盖镜头目标点，主要扫掠只查 Pawn，世界阻挡只检查炮口前 30 cm；在该路径未见完整镜头/炮口两段遮挡和统一防御分支。`DomainOrb.cpp::CheckContact` 直接施加伤害 GE，未见方向防御减伤。需补对照近战统一结算的测试，不能以“已扣血”替代全部攻防验收。

验收：墙在炮口 30 cm 之外仍阻挡；前后防御；普通炮面对闪避免疫；领域球尊重倒地/死亡保护且按设计减伤；只结算一次。对应 M6-T06/T08、SLL-T07/T10。

### A03 蓄力强度与实际成本一致

- [ ] 超级炮按 `clamp((t-1.2)/1.2,0,1)` 增长，最低门槛前仅基础成本；或经明确设计变更同步文档与测试，不能静默改公式。
- [ ] 资源不足时最后支付的部分计入累计成本和强度，不吞掉余额；保持不自动发射。
- [ ] 无限资源检查与扣费统一；切回正常资源清持炮会话，领域开启也遵守训练设置。

依据：`HandleChargeTick` 两种炮共用 `Elapsed/CapTime`，超级炮没有扣除最低门槛；报告中“门槛前收招”实际成本约 **49.167**，与文档“只扣 45”不符。资源不足分支扣剩余咒力但未把余额加入 `PaidCost`。`ModifyEnergy` 未见无限资源豁免，而 `ModifyCursedEnergy` 存在该处理，需验证领域与训练口径。

验收：最低门槛前/恰好门槛/满蓄；普通炮 16 咒力对应最高 60 伤害；正常与无限资源来回切换；不负资源、不双扣、不免费满蓄。对应 M6-T05/T12/T17。

### A04 领域不能给自己充下一次能量

- [ ] 领域期间禁止领域能量获取；普通命中能量按有效结算伤害与攻击实例去重。
- [ ] 修改错误测试预期，并验证领域结束后普通攻击恢复积累。

依据：`DomainOrb::CheckContact` 调用 `GainDomainEnergy`；后者未检查领域有效状态，也未使用传入的攻击实例 ID 去重。M6 报告 `M6-T11_energy_gain_from_hit` 断言领域命中后得到 10 能量，与 08 的“领域期间不自充”相反；阶段文字却称“不自充”。这项不能沿用现有绿色断言作为正确证据。

### A05 领域会话、压制和发射条件

- [ ] 双领域相遇销毁已在飞的领域球，暂停新球；恢复后按原调度点继续，不补发、不冻结球等恢复。
- [ ] 捕获检查实体遮挡/有效参与者；术者受击、倒地、被投和目标保护时跳过新炮。
- [ ] 每球命中校验指定目标与所属有效会话；目标销毁/领域结束/重置立即清球与计时器。
- [ ] 生成成功后才最终提交一次成本，生成失败不吞咒力；自动炮最大伤害/成本与配置来源一致。

依据：`TrainingGameMode::TickDomainSessions` 对已有球调用 `SetOrbPaused`，与设计“清球”不同；已有双领域测试不能覆盖“先飞出球再被压制”。`TryOpenDomain` 已有距离/死亡判断，但未见捕获遮挡；`SpawnDomainOrb` 先扣费再 Spawn，需补失败与状态分支。`DomainOrb` 当前命中条件是非施法者角色，并未显式限定为 Target 或检查 DomainSessionId。

验收：SLL-T23/T24、M6-T10/T22/T23；需制造真实在途球、施法者受击和生成失败等前置，不只检查空列表。

### A06 曲线球的可读性与障碍处理

- [ ] 补障碍处理：可绕则连续绕行，不可达则碰撞销毁，不穿墙/隐藏补伤害。
- [ ] 验证目标失效、超时、近身反向、高速及不同帧率，无漏检/重复命中。

依据：已有向上初速度和转向限速，确实不是仅静态特效；但 `DomainOrb` 根碰撞禁用，扫掠遇非角色阻挡后未见销毁/绕行处理，不能认定障碍规则完成。是否足够弯曲必须实机看。用户已允许球体占位，**无需等待正式咒球美术**。
