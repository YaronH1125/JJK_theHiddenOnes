# 开发计划与验收

版本：v0.3；日期：2026-09-15。本次补充分阶段开发过程文档；当前已有工程文件，以下里程碑的运行完成情况待逐项核验，不据此宣称未创建或已验收。

## 1. 执行方式

按可运行的最小切片推进，每一步先闭环再增加功能。当前没有确定每周投入时间和素材准备程度，因此不承诺固定周数。

每次工作记录：目标、范围、改动、验证、未验证项、问题和下一步。完成标准来自本文件，不以“代码已写完”代替运行验证。

详细开发顺序、自测用例、闭环脚本和阶段交接统一放在 [开发过程文档](开发过程/README.md)。每阶段先核对已有实现，再补缺失项；按用例填写实际结果与证据，完成后同步本页状态。八份文档已经建立，不表示八个阶段已开发或已自测。

M4 先完成静止木桩/固定防御和 AI 切换接口，真实 AI 在 M5 验收；正式技能尚未接入时，用开发测试能力验证真实消耗/冷却规则，M6 再用石流龙正式技能完成集成验收。

## 2. 里程碑

### M0：工程基线

详细文档：[M0_工程基线](开发过程/M0_工程基线.md)。

内容：

- 核对已有 UE 5.8.2 Third Person C++ 工程；仅在工程缺失时新建标准 None 变体，不覆盖当前工程。
- 建立版本控制和适合 Unreal 的忽略规则。
- 保留本套文档，记录引擎、编译器和目标平台。
- 启用 GAS 所需插件/模块，确认一次完整编译。
- 清点 C++ 模板随附变体，先不盲目删除引用。

验收：可进入编辑器并运行第三人称模板，移动与自由镜头正常；没有把旧项目原地升级。

### M1：基础训练擂台

详细文档：[M1_基础训练擂台](开发过程/M1_基础训练擂台.md)。

内容：

- 白盒擂台、边界、两个出生点，按 [07_擂台与视觉参考](07_擂台与视觉参考.md) 的默认参数起步。
- 共享 FighterCharacter、玩家和静止对手。
- 自由镜头、目标选择、手动锁定/回正。
- 双方 ASC、AttributeSet 初始化，训练设置入口占位。
- 提前检查石流龙模型骨骼、比例、头部 Socket 与动作缺口；暂缺素材时用占位模型推进。

验收：双方可生成；镜头自由旋转；锁定身份不强制镜头每帧对准目标；角色转向与镜头互不争抢；初始化不重复。

### M2：单次攻击闭环

详细文档：[M2_单次攻击闭环](开发过程/M2_单次攻击闭环.md)。

内容：

- 一个 GA 普攻、Montage、攻击窗口和命中检测。
- 一个伤害 GE、生命变化、受击反应。
- 最小调试显示、基础重置。
- 确定本批命中结果的处理顺序及普通攻击换血规则。

验收：一次攻击对同一目标不会因多个骨骼/多次查询重复伤害；攻击被中断后检测关闭；死亡/重置后不出现延迟命中；双方同时命中按规则处理。

### M3：连招与核心攻防

详细文档：[M3_连招与核心攻防](开发过程/M3_连招与核心攻防.md)。

内容：

- 三段连击、输入缓存、命中确认和取消窗口。
- 持续防御、方向闪避、行动资源。
- 普攻对防御转投技的最小验证。
- 受击、击退、倒地、起身和死亡完整串联。

验收：缓存不越过动作限制；防御松开不会丢失；只有允许窗口能取消；投技双方中断可恢复；不包含振刀或精确防御分支。

### M4：训练系统

详细文档：[M4_训练系统](开发过程/M4_训练系统.md)。

内容：

- 静止木桩、固定防御与 AI 模式选择入口。
- 完整重置、自动恢复生命、无限生命、无限资源和无冷却。
- UMG 双方属性、冷却、伤害、连击和输入记录。

验收：设置含义一致；无限资源同时影响检查与扣除；无限生命保留伤害统计且不会先触发死亡；重置不重复授予能力或绑定 UI。

### M5：AI 对战

详细文档：[M5_AI对战](开发过程/M5_AI对战.md)。

内容：

- Behavior Tree/Blackboard，已知对手目标。
- 接近、侧移、后退、攻击、防御、闪避。
- 反应延迟、决策间隔和行为偏好参数。
- AI Task 等待共享动作执行结果，处理失败与中止。
- 胜负反馈与重新开始。
- 完成一次 Development 独立运行包验证，提前检查地图、导航和行为树依赖。

验收：AI 通过相同能力和资源规则对抗；不在受击禁止期间强行出招；模式切换后无旧指令残留；胜负后不再继续攻击。

### M6：角色与技能表现

详细文档：[M6_角色与技能表现](开发过程/M6_角色与技能表现.md)。

内容：

- 接入已确认的石流龙，完成模型/骨骼/动画适配与双方识别标记。
- 实现短突进重拳、基础咒力炮击、强化蓄力炮击；工作名与默认规则见 [06](06_石流龙角色方案.md)。
- 迁移炮击瞄准与遮挡算法，使用头部炮口 Socket；旧领域不纳入当前默认首版。
- 特效、声音、受击反馈和镜头打磨。
- 确定并记录正常能量获取规则，复验正式技能的训练开关与 AI 决策，更新独立运行包。

验收：普通技能与绝技都有正常、中断、取消/禁止取消、死亡和重置路径；资源替换不需要复制战斗逻辑；不因追加表现扩大核心系统范围。

### M7：交付与求职展示

详细文档：[M7_交付与求职展示](开发过程/M7_交付与求职展示.md)。

内容：

- 独立运行包、演示视频、操作说明。
- 技术说明：架构、输入到命中链路、关键边界和取舍。
- 一次有记录的性能分析，说明设备、分辨率、场景和数据。
- 清理确实未引用的模板内容和调试默认输出。

验收：新机器或干净运行环境下完成打包运行验证；操作说明与实际按键一致；演示明确区分完成内容和计划内容。

## 3. 关键验收矩阵

| 分类 | 测试情景 | 预期 |
| --- | --- | --- |
| 输入 | 提前按攻击、过期再进入窗口 | 有效缓存执行；过期输入不执行 |
| 输入 | 防御中受击、硬直期间松开防御 | 恢复后不会错误继续防御 |
| 输入 | 快速重复攻击/技能/取消 | 无重复激活、重复扣费或无限取消 |
| 镜头 | 锁定后持续转动镜头 | 保留手动观察，不强行拉回 |
| 镜头 | 靠墙、双方贴近或交叉 | 不严重穿墙，不出现不可控跳转 |
| 擂台 | 沿边移动、向边界突进、受击击退 | 不越界、不跌落；无墙弹或出界胜负；重置回到两出生点 |
| 石流龙 | 玩家与对手镜像生成并各自出招 | 外观标识可区分；资源、冷却和技能实例互不串用 |
| 炮击 | 镜头能看到目标但头部炮口被墙遮挡 | 命中最近阻挡，不穿墙扣血；特效终点与检测一致 |
| 炮击 | 无目标、目标横移、防御或闪避 | 按发射时方向与统一规则结算，空放不追踪补伤害 |
| 强化炮击 | 蓄力中受击、取消、死亡或重置 | 发射前中断无延迟伤害；已提交消耗按默认规则不返还，重置恢复属性 |
| 炮击 | 光束特效跨多帧或能力结束后仍在淡出 | 单段只结算一次；表现不额外造成伤害 |
| 目标 | 目标死亡/销毁/离开范围 | 引用失效可恢复，技能按配置失败或空放 |
| 命中 | 同目标多个碰撞部件 | 同一命中段仅结算一次 |
| 命中 | 攻击窗口多次查询 | 不重复命中，下一合法段可再次命中 |
| 命中 | 双方同批次攻击接触 | 稳定执行已定义的换血/打断规则 |
| 防御 | 正面、侧后方、投技 | 按角度与攻击类型处理 |
| 取消 | 窗口内/外、资源足/不足 | 只在符合全部条件时成功 |
| 位移 | Root Motion 期间 AI 或移动输入 | 无多个控制来源争夺位置 |
| 投技 | 配对后任一方死亡/销毁/重置 | 双方限制与配对引用均清理 |
| 受击 | 霸体中受普通攻击 | 扣血和打断按独立规则结算 |
| 生命周期 | 攻击或蓄力中死亡/重置 | 无延迟伤害、残留窗口或资源扣除 |
| 训练 | 无限资源且原资源不足 | 能正确通过消耗检查 |
| 训练 | 开启无冷却时已有冷却 | 对应冷却清理，后续不新增 |
| 训练 | 连续重置至少 20 次 | 无重复能力、UI 订阅或残留投射物 |
| AI | 进攻中切木桩/固定防御 | 旧行为停止，被动反应正常 |
| UI | 死亡、重开、目标重建 | 属性来源与订阅正确切换 |
| 帧率 | 30/60/120 FPS 观察同类操作 | 记录输入、窗口与检测差异，修复明显漏判 |
| 打包 | 编辑器外运行 | 地图、输入、资源和训练设置正常 |

30/60/120 FPS 用于检查渲染帧率变化带来的问题，不代表已实现固定逻辑帧或确定性联网模拟。

## 4. 调试与性能

- 调试面板显示当前 GA、关键标签、缓存动作、动作阶段和命中结果。
- 可以开启/关闭轨迹与碰撞可视化，正式演示默认关闭。
- 记录活动投射物数量、重复命中和无法结束的能力等异常。
- 优先使用 Unreal Insights 等工具测量实际瓶颈，再决定是否优化 Tick、分配和效果数量。
- 性能报告记录 CPU/GPU、分辨率、画质、运行包类型与测试场景。
- 帧率目标待设备和资源负载明确后确定，不以空擂台数据代表完整技能场景。

## 5. 当前主要风险及对应措施

| 风险 | 对应措施 |
| --- | --- |
| 角色动画资源不足 | 先用模板动作完成闭环，正式素材尽早验证骨骼 |
| 投技双方配对扩大成本 | 只做一个地面投技，先占位验证，明确异常退出 |
| 技能仍堆回 Character | 单个 GA 迁移后验证，不整类复制旧工程 |
| GAS 与手动规则重复 | 属性/冷却/战斗状态指定唯一管理者 |
| 升级、模型、玩法同时改 | 分批迁移，每批保持可运行 |
| AI 与玩家规则不同 | 统一请求与结算，AI 只做决策 |
| 训练重置清理不完整 | 从单次攻击阶段就加入重置回归 |
| 过早追求大招表现 | 核心攻防与训练稳定后再集中打磨 |
