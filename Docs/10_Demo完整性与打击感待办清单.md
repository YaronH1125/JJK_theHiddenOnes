## 1. 现在能否进入 M7

**可以开始 M7 的整合、手感打磨和交付准备。按现有“正式石流龙可独立游玩”的交付标准，尚不能宣布 M7 完成。** 工程已有单角色、单擂台、训练/AI、胜负/重开和炮击/领域原型。现在缺少的是反馈品质、完整操作体验、最终版本证据与正式素材整合，不是从零重搭攻击系统。

用户提到的角色模型、场景美术、近战动作、远程特效属于美术接入工作；此外最值得优先补的是：**战斗音频、分层受击反馈、命中停顿与镜头脉冲、招式节奏/AI 反制、真实输入与有声整局测试、最终操作说明和稳定运行包。** 精细场景装饰不是白盒可玩闭环的硬门槛，球体炮弹仍可用于机制验证。

## 2. 拿到素材后可以做什么

可以把素材接入这个现有 Demo：检查导入 → 骨架/材质与动作适配 → Socket、Montage 和 GA 接线 → 命中与反馈校准 → PIE 验证 → 独立包。素材本身不会自动变成可玩的技能，动作时间、碰撞、取消窗口和资源仍需逐项适配。

| 素材 | 建议提供的内容 | 接入工作与完成标准 |
| --- | --- | --- |
| 石流龙角色 | 已蒙皮带骨骼 FBX 或完整 UE 资产包；贴图、材质、参考姿势、比例与骨架说明 | 建目标 IK Rig/Retargeter，核验肩肘膝、手脚接触、头部炮口；先走跑与一拳验证，再扩展。静态模型若没绑定，需要另做骨架/蒙皮 |
| 动作包 | 源骨架、Animation Sequence/FBX、动作清单、Root Motion/In-place 说明、帧率 | 对齐根运动来源，修脚滑/穿模，分起手/有效/恢复/衔接窗口，接现有 GA，不直接照搬动作包战斗脚本 |
| 场景 | 网格、材质/贴图、单位、碰撞与 LOD；UE 资产完整依赖 | 按素材实测场地配置出生点、边界与导航，保留白盒回归；源素材只读，通过独立玩法层适配，验证角色/相机/炮弹碰撞、遮挡、明暗可读性和性能 |
| 远程特效 | Niagara、材质、纹理等全部依赖；局部/世界空间、缩放及循环参数 | 接头部炮口、蓄力强度、发射与实际命中点；取消/重置清理，关闭特效后伤害仍正确 |
| 战斗音频 | WAV 等可导入文件；拳/腿/格挡/蓄力/发射/命中/落地分类及来源 | 做声音变体、衰减、并发与音量优先级；空挥和命中分开，满蓄提示单次，取消结束循环声 |

接入时保留来源与可使用范围记录即可。不是要求购买特定资源包，也不要求先把所有美术凑齐。

### 2.1 简单动作可以制作到什么程度

**可制作/修改功能性简单动作，并做进 Demo。** 优先在可用骨架和控制器上关键帧制作，或重定向已有动作后局部修正；不能保证凭一个未绑定静态模型就自动产出成熟商业动作包。

| 适合先做 | 方式与验收 |
| --- | --- |
| 蓄力准备、持炮循环、释放后坐、收招 | 上半身关键姿势与短过渡；下半身站定或移动分层；炮口方向可读 |
| 防御姿势、短促格挡震动、轻受击 | 简单骨盆/胸肩/手臂姿势及 Additive 层；命中方向一致，不影响胶囊规则 |
| 基础直拳、侧踢的原型 | 少量关键姿势，明确重心和接触点；先保证读得懂、不会脚滑，再打磨 |
| 简单结印、领域展开姿势 | 短姿势演出与事件点；手指骨骼不足时允许简化，不假装完成原作手印精度 |

复杂连续拳脚、双人投技配对、高质量翻滚、布料/长发和电影级表演通常需要更成熟的基础动画或额外人工迭代。重定向只解决骨架映射，不自动解决力量感、脚底锁定和人物性格。Epic 的 [IK Retargeting](https://dev.epicgames.com/documentation/en-us/unreal-engine/ik-rig-animation-retargeting-in-unreal-engine) 与 [Control Rig](https://dev.epicgames.com/documentation/en-us/unreal-engine/control-rig-in-unreal-engine) 提供相应工作流，实际接口按本机 UE 5.8.2 核验。

## 3. 打击感研究：哪些证据可以借鉴

本次优先使用开发者访谈、官方发布与引擎文档。以下游戏的内部参数没有公开就不编造；公开介绍、开发者自述和本项目设计推论分开写。官方视频只核验到来源/主题，未取得完整字幕或逐帧分析，不能据此宣称“鸣潮使用固定多少毫秒顿帧”。

### 3.1 鸣潮：重点借鉴“整条战斗链统一”，不只借粒子

库洛在 Epic 访谈中明确谈到动作、选敌算法与特效更新的优化，以及让战斗具有深度和乐趣。这支持把响应性、选敌、动作和性能一起检查，而不是仅以连招数量衡量战斗。[开发团队访谈](https://store.epicgames.com/en-US/news/wuthering-waves-interview-kuro-games-launch-struggles-future-plans)

另一篇 Unreal Engine 访谈提供更具体的制作线索：角色动作围绕独特特征设计；表现尽量可关键帧控制；大招演出可细调震动强度/频率；材质控制与 Niagara 用于统一战斗视觉。这些是公开制作方法，但不等于所有普攻的内部实现。[Unreal Engine 库洛访谈](https://www.unrealengine.com/developer-interviews/exploring-the-post-apocalyptic-charm-of-asg-open-worlds-in-wuthering-waves)

应用到石流龙的建议（本项目原创方案）：

| 鸣潮方向带来的启发 | 我们具体做什么 | 不直接照搬什么 |
| --- | --- | --- |
| 动作有角色辨识度 | 近战明确送肩、转髋、蹬地；炮击“聚集—发射—后坐—收势”一套重炮气质 | 不给所有招式同一动画播放速率与同一音效 |
| 技能循环的视觉语言统一 | 普通炮、超级炮、领域球共享咒力色系，亮度/体积/尾迹区分等级，反馈服从真实强度 | 不用颜色堆出额外元素伤害，也不以满屏光遮住对手 |
| 操作与反馈联动 | 锁定目标可靠，击中/防住/免疫分别表达，连招衔接与重击准备看得见 | 不为模仿动作 RPG 增加三人换人、协奏、声骸或新弹反机制 |
| 演出按场景控制 | 轻拳小反馈、重击集中爆发、炮击先发射后命中；鼠标镜头保持控制 | 不重新引入用户已拒绝的近战自动回正 |
| 性能也是手感 | 特效并发和帧时间稳定，低画质仍看清出招/命中 | 不只在静态截图或空场景证明“流畅” |

后续若做鸣潮逐帧参考，选“一次轻击、一次重击、一次成功防守反馈、一次蓄势释放”各一段，分别标出输入响应、接触、声音起点、受击、镜头峰值和恢复；不要比较不同 FPS 视频的裸帧数。先记录观察，再提出本作参数，不把观察推断当作库洛实现揭秘。

官方资料入口：[早期战斗策划访谈](https://www.taptap.cn/moment/349636079751529888)、[2025 战斗系统开发深访视频](https://www.youtube.com/watch?v=SKn6C1AEjqg)。早期资料仅作历史设计参考，不当作当前版本精确规则。

## 4. 石流龙的第一版打击反馈方案

### 4.1 先做一个完整样板招式

先把 A1 和重拳各做成一个反馈样板，再扩到腿击与炮击。双方使用当前占位模型也能验证，不必等四类正式美术全部到齐。

顺序：①姿势/接触点校准 → ②方向性受击 → ③空挥与命中音 → ④短命中停顿 → ⑤镜头脉冲 → ⑥小命中特效 → ⑦连续实战。每加一层做开/关对比，找出真正改善手感的部分。

### 4.2 调参起点（全部为本项目建议，不是参考游戏数据）

| 结果 | 局部 hit stop 起测范围 | 声音/受击/镜头重点 |
| --- | --- | --- |
| 空挥 | 0 ms | 只有挥动声与动作，无命中闪光或命中震动 |
| A1/A2 轻拳 | 25–40 ms | 清晰短瞬态、轻受击、极小镜头脉冲，留下一击空间 |
| A3/重拳 | 50–80 ms | 更重的接触声与躯干折叠/击退，短促较强镜头反馈 |
| 轻腿/重踢 | 轻腿 30–45 ms；重踢 50–80 ms | 腿击风声与更大身体反应；重踢倒地遵守现有保护 |
| 格挡 | 15–30 ms | 紧凑格挡声、手臂/上身震动；不得播出“命中肉体”的反馈组合 |
| 闪避免疫 | 0 ms 命中停顿 | 只播放真实成功闪避反馈，不能凭附近空挥触发 |
| 移动炮接触 | 0–25 ms（可先不暂停术者） | 发射与命中声音分开，距离真实；小冲击与受击方向清晰 |
| 超级炮/领域球接触 | 25–60 ms，逐炮限频 | 低频与清晰爆发，远程术者不因每颗球反复停住；连续球不无限叠震 |

参数以秒计，与渲染帧率解耦；60 FPS 下 1 帧约 16.7 ms 仅供理解，不能实现成“固定卡 3 个渲染帧”。先不开全屏闪白、色差与每击 FOV 变焦；可提供镜头震动 0/低/标准设置。

### 4.3 与现有 GAS/时间逻辑的接法

这部分是后续实施方案，尚未实现：

- 近战/炮弹/领域球在最终接触结果确定后发一条反馈事件，携带攻击实例、目标、命中点、来向、命中/格挡/免疫/击倒结果和反馈等级。单次结果只消费一次。
- 挥动声可由动作通知触发；命中声、震动和受击特效必须由真实结算结果驱动。不能只凭动画走到某帧就播放命中。
- 可用一个小型 FeedbackProfile 数据资产和薄组件管理音效、镜头与局部停顿，不重写战斗状态机。规则层决定伤害和可打断，表现层不二次扣血。
- 首轮不全局暂停世界。先做参与角色的局部停顿；输入采集继续，动作时间、Montage、Root Motion、命中采样和取消/衔接窗口必须采用一致暂停口径。仅将 Montage 播放率归零、让 GA 的世界计时器继续走，会导致丢通知和错过窗口，不能作为完成实现。
- 局部停顿结束采用不被自身暂停阻断的时钟；同帧多命中取受控最大值，不逐次相加形成永久冻结。死亡/重置/失焦的清理优先，恢复原播放率和移动状态。
- 音频优先保证敌人起手和有效命中可听，蓄力循环不淹没反制提示。限制同类并发，禁止把增大总音量当成力量感。[Epic 声音并发文档](https://dev.epicgames.com/documentation/unreal-engine/sound-concurrency-reference-guide)
- 镜头使用轻量局部位移/旋转并及时回落，不改玩家控制器瞄准基准，不重启自动索敌；远程准星/弹道在开关震动时保持一致。[Epic Camera Shakes](https://dev.epicgames.com/documentation/unreal-engine/camera-shakes-in-unreal-engine)

### 4.4 蓄力与领域的反馈重点

蓄力有四个可区分状态：起手、增长、满蓄保持、取消/释放。增长时音高/亮度渐变，满蓄只有一次提示并进入稳定循环，保持 60 秒不会无限变响或叠粒子。咒力受限使用不同提示，不能冒充真正满蓄。

手动炮在发射时给炮口声和身体后坐，在真实命中时给目标冲击声/受击；射空不会听到近身命中声。领域曲线球用“出现—弧线移动—接触爆发”表达，不靠巨量烟火掩盖弹道；优先确保对手仍可辨识。
